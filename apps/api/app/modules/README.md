# 业务模块边界

| 模块              | 职责                                                 |
| ----------------- | ---------------------------------------------------- |
| `product_board`   | 现行商品事实规范化、不可变接收、查询、经营指标与风险 |
| `product_scoring` | 商品参考特征、试行标准、计分及相容结果发布           |
| `promotion`       | 推广双模式聚合与确定性诊断                           |
| `sales`           | 店铺日、续段来源、地区和目标查询及发布               |
| `aftersales`      | 售后金额、分类、期间报告、分析及目标                 |
| `weather`         | 天气文档契约、解析、归档及查询                       |

运营中心在前端组合既有域 API，不再复制一套后端经营规则。旧 `products` 模块已移除，前端 `features/products` 仍为现行商品页面，两者不要按同名推定关系。

每个域按实际需要包含契约、查询、规则和仓储，不预建空层。路由只处理协议，仓储处理数据库，连接器处理来源；仓储不生成建议文本，连接器不处理界面状态。跨域依赖必须固定相容输入版本，字段与接口以[数据契约](../../../../docs/data-contract.md)为准，目录与全局职责见[架构](../../../../docs/architecture.md)。
