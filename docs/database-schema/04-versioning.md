# 04 版本、任务与覆盖（5张）

本地创建、接收、封版、任务转换和入口切换时间均由数据库/受控程序按真实事件自动维护，来源时间不套自动now；详细规则及30表索引清单统一见[公共字段规范](README.md#common-field-policy)及[查询索引设计](README.md#query-index-design)。不可变内容不增加通用updated_at/deleted_at。

本文件是[30表现行设计](README.md)的支撑部分，只包含下列5张表。它们让五页能说明“读了哪份数据、何时成功、缺什么、旧报告能否重读”，不建立通用调度或来源管理平台。公共命名、数值、外键与删除规则见[统一字段规范](README.md#统一字段规范)。本文是设计字典，不直接执行；结构及验证统一见[迁移方案](migration-plan.md)。

## `dataset_versions`

**对象与粒度：**一逻辑数据集的一份不可变、可重读输入或产物。`source`表示实际接收的原始必要投影；对既有输入重新解析、映射或计算产生`derived`版本，并用`version_inputs`固定父输入。一个版本只发布一个逻辑用途；J2与J3即使字段相同也分别标为`jst_shipped_sales`与`jst_cancelled_sales`。

| 字段                      | 含义                               | PostgreSQL类型 | 可空 | 键/引用             | 默认/说明                                                                                                                                                                                     |
| ------------------------- | ---------------------------------- | -------------- | ---- | ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`                      | 版本标识                           | `TEXT`         | 否   | PK                  | 应用生成稳定、不含凭据的字符串                                                                                                                                                                |
| `dataset_code`            | 逻辑数据集代码                     | `TEXT`         | 否   | UQ一部分            | 代码清单见本文；同逻辑范围一次只生效一个来源                                                                                                                                                  |
| `origin_kind`             | 来源接收或派生产物                 | `TEXT`         | 否   | CHECK枚举           | `source / derived`                                                                                                                                                                            |
| `state`                   | 校验与发布状态                     | `TEXT`         | 否   | CHECK枚举           | `draft / validated / published / rejected`；调用者明确赋值                                                                                                                                    |
| `source_system`           | 实际物理来源系统                   | `TEXT`         | 是   | 无                  | 仅source必填，数仓、聚水潭或飞书；derived沿输入追溯                                                                                                                                           |
| `source_locator`          | 实际交付/表/工作表定位             | `TEXT`         | 是   | 无                  | 仅source必填；不含连接串、token、查询私密参数                                                                                                                                                 |
| `row_schema_revision`     | 本版本必要投影的字段结构修订       | `TEXT`         | 否   | 无                  | 精确不可变修订；不是可变的“最新版”别名                                                                                                                                                        |
| `interpretation_ref`      | 已冻结的字段、范围及口径解释证据   | `TEXT`         | 否   | 无                  | 指向按内容摘要固定的契约/映射；含来源命名空间、真实粒度、单位、日期、时区、空值及修订删除语义                                                                                                 |
| `producer_revision`       | 实际接收器或计算代码修订           | `TEXT`         | 否   | 无                  | 对应本次实际执行内容；不使用可变分支名                                                                                                                                                        |
| `rule_set_id`             | 实际使用的解释/计算规则参数包      | `TEXT`         | 是   | FK → `rule_sets.id` | 不使用业务参数包时为空；评分/风险/推广/售后/中心实际规则绑定相容包；标准导入及profile_records/profile_links用固定来源/解释/代码，保持NULL。标准不因计分包不同而复制，部分确认只启用已确认分支 |
| `content_fingerprint`     | 内容及语义输入的稳定摘要           | `TEXT`         | 是   | UQ一部分            | draft可空；validated/published必填；相同输入复用版本，不作为业务行去重键                                                                                                                      |
| `retained_input_ref`      | 必要原交付的受控留存位置           | `TEXT`         | 是   | 无                  | 显式列已足够重读时可空；不足时必须有可校验、可恢复的原投影，不保存整库或签名下载密钥                                                                                                          |
| `upstream_revision`       | 上游明确提供的版本/交付修订        | `TEXT`         | 是   | 无                  | 只保真实上游值；derived为空；缺失不以接收时刻伪造                                                                                                                                             |
| `period_start`            | 上游或报告明确声明的实际覆盖起日   | `DATE`         | 是   | 成对CHECK           | 与period_end同时有值或同时空；不是请求范围、文件名推测或最小事实日                                                                                                                            |
| `period_end`              | 明确声明的实际覆盖止日             | `DATE`         | 是   | 成对CHECK           | 起止均含当日；不同来源的确认日/支付日仍各自解释                                                                                                                                               |
| `source_cursor`           | 已核可靠的上游续读位置             | `TEXT`         | 是   | 无                  | 仅source且已有修订/删除语义证明才可填；未知为空，不以dt/create_time代替                                                                                                                       |
| `received_at`             | 该份source内容首次实际接收完成时刻 | `TIMESTAMPTZ`  | 是   | 状态校验            | source封版前必填，derived为空；不当成上游更新时间                                                                                                                                             |
| `created_at`              | 本地候选版本实际创建时刻           | `TIMESTAMPTZ`  | 否   | 无                  | 实际事务事件，可默认事务时间                                                                                                                                                                  |
| `sealed_at`               | 内容及输入绑定实际封版时刻         | `TIMESTAMPTZ`  | 是   | 状态校验            | validated/published必填；本地生成报告时间从此读取，不复制到报告头                                                                                                                             |
| `validation_evidence_ref` | 校验通过或拒绝的脱敏证据           | `TEXT`         | 是   | 状态校验            | validated/published/rejected必填；包含检查范围及失败项，不能只写“通过”                                                                                                                        |

**键与约束。**PK为`id`；额外UQ为`(dataset_code, content_fingerprint)`，摘要为空的draft不参与内容复用。代码/修订/引用非空白；期间成对且起日不晚于止日。source必须有物理定位，derived的source_system/source_locator/upstream_revision/source_cursor/received_at为空。validated/published的摘要、封版时刻、校验证据非空；封版不得早于创建。来源接收完成不得晚于封版。拒绝版本不会成为当前指针。

**摘要与不可变边界。**摘要覆盖必要原值和产物的业务语义、来源/命名空间、真实范围、结构/解释/代码/规则修订、独立覆盖证明、各输入版本及角色窗口；排除本地代理ID、运行ID、尝试次数、本地创建/封版时刻和本次观测时刻。来源明确交付的修订/可靠游标是续读语义，不能因数据行同值而遗漏；仅有不同本地观察时间则复用同版本。真实同值新来源或新解释不是同一版本。封版后业务行、结构解释、规则、覆盖证据和输入关系不再改写；发布仅允许`validated → published`等合法元数据状态迁移，已发布历史保持可读。回补、更正、删除和映射修订生成新版本，不能修改旧事实后只换一个ID。若来源只给增量，必须有已核的键/删除语义及上一完整输入，派生出新的完整可读版本；未核时只采用获准范围的全量重读。

**报告幂等和语义。**售后报告摘要还包括逻辑报告键`(report_type,period_start,period_end)`、实际原报告标识/标签/原生成时间/外链、上期及去年具体报告修订ID与比较状态/原因、其实际输入与规则。原生成时间是业务来源值，不能作为本地观测时间排除。排除本地`revision_no`和新代理ID：相同语义先复用已有版本/报告，不先分配修订号导致每次重试都新建一份；确有输入、比较绑定或原报告语义变化，才在逻辑报告键的并发锁下分配新修订号。旧报告内容和比较绑定不可改写。

**资料和标准边界。**`profile_records`只允许source必要原行，解析/映射/日期适用变化只出新的derived `profile_links`，直接绑定原source版，不复制原格或保存全量词元。`score_standards`的完整批次内按standard_code唯一，不另立全局自身修订；实际来源修订保留在来源交付证据。标准冻结原指标签名/单位/窗口/参照依据，评分版绑定实际计分/建议包，逐指标按这些语义判相容，不要求两者规则包ID相同。固定显示标准仍属试算，不因解耦获得正式可信状态。

**关系与范式。**版本1:N事实/资料/目标/标准/评分，版本1:0..1售后报告；规则包1:N使用版本。这里描述交付的共同语义，行里只保行本身实际提供的日期和原键；不能把版本实际期间复制成每行的来源日期。没有`source_datasets`或独立执行定义依赖。版本不会因为不再“当前”而删除；引用删除默认RESTRICT。

## `version_inputs`

**对象与粒度：**一个派生输出版本在一个明确角色上实际使用的一份固定输入。一个输入可供多个结果使用，一个结果有多个不同角色，所以版本间是N:M；本期每个输出的每个角色只允许一份输入，不建设同角色按店铺/日期混源分片。

| 字段                | 含义                         | PostgreSQL类型 | 可空 | 键/引用                              | 默认/说明                                      |
| ------------------- | ---------------------------- | -------------- | ---- | ------------------------------------ | ---------------------------------------------- |
| `output_version_id` | 派生输出版本                 | `TEXT`         | 否   | PK一部分；FK → `dataset_versions.id` | 必须为derived                                  |
| `input_role`        | 该输入在输出中的明确业务角色 | `TEXT`         | 否   | PK一部分                             | 非空有限角色，不由表名随意拼接                 |
| `input_version_id`  | 实际使用的已封版输入         | `TEXT`         | 否   | FK → `dataset_versions.id`           | 不允许指回输出本身                             |
| `window_start`      | 此角色实际使用/请求的起日    | `DATE`         | 是   | 成对CHECK                            | 只有计算确有窗口时填；不是为缺失的源期间补日期 |
| `window_end`        | 此角色实际使用/请求的止日    | `DATE`         | 是   | 成对CHECK                            | 与起日同空或同有，起日≤止日；含当日            |
| `usage_note`        | 特殊范围或兼容性证据说明     | `TEXT`         | 是   | 无                                   | 无需解释时为空；不藏另一套输入版本或对象ID数组 |

**键与约束。**PK为`(output_version_id, input_role)`，同时实现“输出/角色唯一”；无其他UQ。外键均RESTRICT。CHECK检查有限角色枚举（下表列出的15个角色）、非空白、自引用禁止及成对日期。输入已封版与derived输出由迁移保护触发器兜底，角色用途/范围等仍由受控发布器核验。发布前在事务内检查无环、输入已validated/published、输入数据集与角色相符、范围/单位/期间可比；这些涉及跨行跨表，不能声称一个普通CHECK即可保证。source版本没有输入边；重新解释source内容时产物为derived。

| 输出用途            | 输入角色及约束（缺失不得造假，结果按实际缺项门控）                                                                                                                                                                                                                                                                                                                                      |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 原交付规范化/重映射 | `source`绑定必要原交付；如另使用明确映射交付，则增加有固定契约的`scope_mapping`角色                                                                                                                                                                                                                                                                                                     |
| `profile_links`     | 唯一`profile_records`角色绑定一份source原行版；关系中的profile_record_id必须属于该版。解析/映射/日期适用修订仅换本输出，不复制原行                                                                                                                                                                                                                                                      |
| 评分标准计算        | 当前来源导入标准用`source`固定真实标准原交付及已核单位/指标签名；不伪造历史样本计算。只有将来真实参照生成规则已具备并获准时才绑定其实际历史输入/规则，不能据当前字典自动启用                                                                                                                                                                                                            |
| `product_scores`    | 发布评分必须有真实`product_current`且window_start/end明确为连续7日；`product_previous`、`ad_current`、`profile`、`standard`真实缺失时不造边，相应分项不得有效。整份当期输入未接收只返回任务/待输入状态，不存无评分日结果。profile指向profile_links版并沿它读取source原行；standard指向完整标准批次，逐指标校验定义/单位/窗口相容，不强求计分包ID相同；实际额外历史另用`product_history` |
| 目标规范化          | `target_source`；只有实际使用范围映射/独立名单才增加`scope_mapping / scope_list`，不能将未知范围当全店                                                                                                                                                                                                                                                                                  |
| `aftersales_report` | `j1_returns / j2_shipped_sales / j3_cancelled_sales / targets`分别固定真实输入；targets仅在实际应用相容目标时绑定，否则明确待设/待确认；不能以J1推算J2/J3或把缺失当0；比较报告另由报告自FK固定，同期间修订不可当上期；具体期间/修订选择见03                                                                                                                                             |

评分商品本期/前期可以引用同一完整商品版而窗口不同；一个版被不同角色引用合法。对J1的window仍按确认期间解释，对J2/J3仍按支付期间解释；日期数字相同不代表订单链或日期含义相同。未适用/缺失角色与完整结果的区别按03状态门控表达，不插入假的空数据版本冒充已接收。

**范式。**窗口依赖“输出＋角色”这条使用关系；不重复保存输入dataset_code、物理来源、代码修订或规则包。图仅记录真实数据血缘，不记录页面对象、规则命中或任务定义。

## `current_datasets`

**对象与粒度：**一个逻辑数据集的当前可用、所声明内容可完整重读的版本入口。它不证明来源经营齐数，完整性仍须独立证据。无可用版本时没有该行；合法空交付仍须是一份有证据的版本，不能以无指针表示业务0。

| 字段           | 含义                 | PostgreSQL类型 | 可空 | 键/引用                    | 默认/说明                                    |
| -------------- | -------------------- | -------------- | ---- | -------------------------- | -------------------------------------------- |
| `dataset_code` | 逻辑数据集代码       | `TEXT`         | 否   | PK                         | 每代码最多一条当前入口                       |
| `version_id`   | 当前已发布版本       | `TEXT`         | 否   | FK → `dataset_versions.id` | 与本行dataset_code一致，跨表校验             |
| `revision`     | 该入口的并发修订号   | `BIGINT`       | 否   | CHECK≥0                    | 首次0，此后每次成功切换递增，不是业务版本ID  |
| `updated_at`   | 入口实际成功切换时刻 | `TIMESTAMPTZ`  | 否   | 无                         | 写入事务事件，不以它替代上游更新时间或完整日 |

**键与约束。**除PK无额外UQ；version_id普通FK。发布事务检查对应版本为published且dataset_code相同；同一逻辑范围只有一个生效来源，不以新增别名代码规避切源对账。用行锁/修订比较串行化竞争发布；一次改变相关数据集时按稳定顺序锁定，相关指针与已核可靠水位一起提交。可靠续读位置在对应源版本中冻结，不另造第二套水位表。

**报告当前入口。**`current_datasets.aftersales_report`只指向按03规则选出的默认最新报告版；先对每个逻辑期间选择已发布有效修订，再按既定期间/类型顺序选默认。旧期补报可以发布并进入历史，但后完成不使默认入口倒退。历史查询显式固定报告ID及其输入，旧修订保持可查；请求新默认入口不等于重绑历史比较。

**一致读。**API在同一数据库一致快照内取得数据版本，并固定部署配置实际指定的规则包ID、领域计算代码及解释/配置修订，共同构成响应向量；即时查询不按最新规则时间选包，固定方式见README。跨请求带向量/摘要，任一组成失效时按契约整组重取。新事实与旧评分依赖不相容时显示待重算；任务失败不切换当前入口。历史报告显式选历史版本，不受“当前”入口替换影响。这里的四域版本向量不是新增通用发布清单表，也不要求Redis。

**关联、删除与范式。**一个逻辑数据集最多一条当前入口；结合dataset_code相容校验，一份版本只能被其所属用途的入口选中。指针可在发布事务中更新，已发布内容仍不可原地修改。version_id的FK遵守RESTRICT/NO ACTION，不能因切换入口删除旧版本；初始基线禁止DELETE当前入口，防止删除重建将revision重置为0而复用旧并发令牌；停用/撤销的专用语义尚未设计，须另行评审，不能借删除指针清除历史。四个原子属性依赖dataset_code，版本的来源、规则、状态和窗口沿FK读取，不重复存储，符合1NF/2NF/3NF。

## `task_runs`

**对象与粒度：**一次实际接收、规范化、评分或报告尝试。失败重试是新行；多次幂等尝试可复用一个已有内容版本，故任务N:0..1版本，版本1:N任务，不使用一对一输出表。

| 字段                        | 含义                           | PostgreSQL类型 | 可空 | 键/引用                    | 默认/说明                                                                  |
| --------------------------- | ------------------------------ | -------------- | ---- | -------------------------- | -------------------------------------------------------------------------- |
| `id`                        | 本次实际尝试标识               | `TEXT`         | 否   | PK                         | 每次重试独立生成                                                           |
| `job_code`                  | 实际任务种类                   | `TEXT`         | 否   | 无                         | 固定接收/规范化/评分/报告代码，无独立任务定义主表                          |
| `request_ref`               | 该尝试获准请求的冻结描述       | `TEXT`         | 否   | 无                         | 明确字段、必要对象范围、请求窗口、目标用途；脱敏，不藏业务原行或重复血缘图 |
| `retry_of_id`               | 直接重试的前次尝试             | `TEXT`         | 是   | FK → `task_runs.id`        | 根尝试为空；不等于输入数据版本                                             |
| `lock_key`                  | 会相互冲突的实际任务范围键     | `TEXT`         | 否   | 条件UQ                     | 相同源/目标及可能重叠范围必须归同冲突键；不以不同请求ID绕开                |
| `status`                    | 实际执行状态                   | `TEXT`         | 否   | CHECK枚举                  | `queued / running / succeeded / failed / cancelled / abandoned`            |
| `queued_at`                 | 实际入队/登记时刻              | `TIMESTAMPTZ`  | 否   | 无                         | 可默认事务时间                                                             |
| `started_at`                | 实际开始执行时刻               | `TIMESTAMPTZ`  | 是   | 状态CHECK                  | queued为空；开始后保留                                                     |
| `finished_at`               | 实际结束或宣布遗失的时刻       | `TIMESTAMPTZ`  | 是   | 状态CHECK                  | 所有终态必填，queued/running为空                                           |
| `worker_ref`                | 当前/最后实际执行者标记        | `TEXT`         | 是   | 状态CHECK                  | running必填；不保存机器秘密或人员指派                                      |
| `lease_expires_at`          | 本次运行租约截止时刻           | `TIMESTAMPTZ`  | 是   | 状态CHECK                  | running必填；终态为空，续租为真实事件                                      |
| `result_version_id`         | 本次产生或复用的版本           | `TEXT`         | 是   | FK → `dataset_versions.id` | 未产出为空；成功必须有validated/published产物，失败可留真实隔离候选        |
| `source_updated_text`       | 本次实际看到的来源更新时间原文 | `TEXT`         | 是   | 无                         | 未读取/未提供时为空；不把本机时间装成源时间                                |
| `source_updated_at`         | 有时区依据可解析的来源更新时间 | `TIMESTAMPTZ`  | 是   | 跨字段CHECK                | 无时区/不能解析时为空并保原文；解析依据在来源解释中                        |
| `source_update_observed_at` | 本次观察到上述原文的实际时刻   | `TIMESTAMPTZ`  | 是   | 跨字段CHECK                | 有原文时必填，不因内容版复用而覆盖旧观测                                   |
| `error_code`                | 失败/取消/遗失的稳定原因代码   | `TEXT`         | 是   | 状态CHECK                  | failed/abandoned必填，成功为空                                             |
| `error_summary`             | 脱敏的人可读原因               | `TEXT`         | 是   | 无                         | 不含凭据、完整业务行及敏感查询参数                                         |
| `evidence_ref`              | 实际执行及失败排查证据         | `TEXT`         | 是   | 无                         | 必要日志/校验摘要引用；不代替版本的封版校验证据                            |

**键与约束。**PK为id；额外条件UQ为`lock_key WHERE status=running`，不把当前时钟写进索引谓词。任务与直接重试不得自指/成环，必须同一实际任务目的，前次为终态；这是发布/执行服务的跨行检查。queued没有起止执行时间；running有started/worker/lease且无finished；终态有finished，开始过的结束不早于开始，所有开始/结束不早于queued。source_updated_at非空必须有原文；有原文必须有观测时间，三者无观测时全空。原文与可解析时刻不是重复业务事实，而是解释失败时仍必须保留的来源证据。

**恢复及发布。**过期租约不能自动释放仍running的唯一键。先在锁内将旧尝试标abandoned、记录原因，再启动新尝试；每次写入/封版/发布都核验当前尝试和租约，旧worker不得越过新尝试写入。相同内容通过版本摘要复用；不设“同查询永远只能成功一次”的唯一键，因为上游同范围可能回补。重试预算、超时及来源并发按实测/批准配置，未确认的上游5并发不当事实。task_runs的任务结束不代表业务数据已完整，页面成功时间只取与所读版本关联的真实成功记录/封版事件。

**范式。**这里只保一次尝试及实际观测；数据集、规则、代码及输入依赖从result_version追溯，不复制多套固定配置。源内容未变也可有新观测，不覆盖不可变版本来更新网页来源时间。历史记录外键均RESTRICT。

## `coverage_records`

**对象与粒度：**一个版本在一个实际对象/可选字段/窗口上的独立、有证据的可用性与完整性结论。它不是经营行数/最大日期缓存，也不意味着有记录就是完整。

| 字段                    | 含义                              | PostgreSQL类型 | 可空 | 键/引用                    | 默认/说明                                                            |
| ----------------------- | --------------------------------- | -------------- | ---- | -------------------------- | -------------------------------------------------------------------- |
| `id`                    | 覆盖证据标识                      | `TEXT`         | 否   | PK                         | 应用生成                                                             |
| `dataset_version_id`    | 被判断的固定版本                  | `TEXT`         | 否   | FK → `dataset_versions.id` | 与被读事实/结果一致                                                  |
| `scope_kind`            | 证据适用对象层级                  | `TEXT`         | 否   | CHECK枚举                  | `dataset / shop / shop_channel / listing`                            |
| `shop_id`               | 店铺范围                          | `TEXT`         | 是   | FK → `shops.id`            | 仅shop/shop_channel必填；listing范围不重复店铺                       |
| `channel_code`          | 店铺渠道范围                      | `TEXT`         | 是   | 有限代码CHECK              | 仅shop_channel必填；不关联渠道主表                                   |
| `listing_id`            | 商品链接范围                      | `TEXT`         | 是   | FK → `listings.id`         | 仅listing必填，通过链接取得店铺                                      |
| `field_code`            | 必要字段级证据对象                | `TEXT`         | 是   | 无                         | 空表示整份对象范围；非空必须是该数据集实际定义字段                   |
| `window_start`          | 本证据覆盖窗口起日                | `DATE`         | 是   | 成对CHECK                  | 无窗口的来源/交付级证据可空                                          |
| `window_end`            | 本证据覆盖窗口止日                | `DATE`         | 是   | 成对CHECK                  | 与起日同空或同有，起日≤止日                                          |
| `availability_state`    | 数据存在/缺失的具体状态           | `TEXT`         | 否   | CHECK枚举                  | `observed / no_records / not_received / field_null / not_applicable` |
| `completeness_state`    | 此范围是否完整                    | `TEXT`         | 否   | CHECK枚举                  | `unknown / partial / complete / not_applicable`                      |
| `complete_through`      | 有独立证明的完整截至日            | `DATE`         | 是   | 状态校验                   | 最大事实日不可代替；无完整日证明为空                                 |
| `expected_record_count` | 上游/业务约定明确提供的应有记录数 | `BIGINT`       | 是   | CHECK≥0                    | 无明确权威不填；不默认每天应恰有一行                                 |
| `expectation_ref`       | 应有范围、行数或完整日的权威依据  | `TEXT`         | 是   | 状态校验                   | complete、完整日或应有行数任一出现均必填                             |
| `reason_code`           | 该状态的稳定解释代码              | `TEXT`         | 否   | 无                         | 例如源未交付/字段未提供/明确无记录；不是业务0                        |
| `evidence_ref`          | 这次覆盖判断的脱敏证明            | `TEXT`         | 否   | 无                         | 有记录、缺记录和失败须可区分                                         |
| `checked_at`            | 判断实际完成时刻                  | `TIMESTAMPTZ`  | 否   | 无                         | 封版后不改写；新证据产生新版本/判断版                                |

**键与约束。**PK为id；额外UQ为`(dataset_version_id, scope_kind, shop_id, channel_code, listing_id, field_code, window_start, window_end) NULLS NOT DISTINCT`，避免可空范围重复结论。日期成对有序。scope_kind决定唯一合法列形状：dataset全空；shop仅shop_id；shop_channel仅shop_id+channel_code；listing仅listing_id。`field_null`要求field_code非空；`not_applicable`须有不适用依据。complete_through不晚于本证据有界窗口止日；不从这个条件推导来源每天完整。应有行数及完整日均需expectation_ref；完整状态也需权威范围。跨表验证数据集、渠道及事实范围相符，所有FK默认RESTRICT。

**状态边界。**真实0只存在明确收到的事实数值中；`no_records`仅表示实际查/收到的集合无行，能否视为业务0还须明确来源契约；`not_received`与接收任务失败分别由证据/任务表达；`field_null`保留无值原因，不能补0。actual行数、缺日列表、最早/最新日从固定事实版本查询，不在此再存副本。该表保存独立覆盖证明，不以额外覆盖副本制造反范式。

**关联、删除与范式。**版本1:N覆盖记录；店铺/链接各可有多份历史范围证明，一条证明按scope_kind仅引用实际需要的店铺或链接，不重复链接所属店铺。父版本和实体FK均RESTRICT，已发布证明随版本保留，新证据追加新版本。状态、完整日及依据依赖完整的版本—范围—字段—窗口业务键，各值原子且不保存实体名称或事实合计，符合1NF/2NF/3NF。

## 逻辑数据集与发布边界

本期有限逻辑代码包括`profile_records / profile_links / product_daily / shop_daily / product_promotion / shop_channel_product_promotion / shop_channel_star_shop / shop_ratings / shop_refunds / shop_regions / product_regions / jst_shipped_sales / jst_cancelled_sales / jst_returns / sales_targets / refund_targets / score_standards / product_scores / aftersales_report`。实际原交付如需先留存、再规范化，使用明确定义的`*_source`用途，不新增物理表；只保存本项目获准必要投影。概览与明星店铺因实际业务范围不同有独立代码与来源，两者仍落shop_channel_promotion_daily，分别聚合后组合；同渠道同范围的旧补齐源与数仓仍只能生效一个。dataset_code不是随意扩张来源范围的许可。

发布前必须核对：来源单一且获准、资料原行source/关系derived边界、标准/计分指标签名相容、报告期间与修订选择、业务键/真实粒度、字段/单位/空值、角色输入及窗口、完整性证据、全部FK/集合约束、摘要和真实重读路径。受控发布事务须先按稳定版本ID顺序对待封版输出取得FOR UPDATE行锁，再读取并校验其内容/成员/输入/覆盖；不能先校验再取锁，否则会漏验并发写入。全部通过后在同一事务内封版、置发布状态并切相关当前入口；若计算已封版后才发布，仅发布元数据和指针改变。失败保持旧有效指针及可靠水位；修复、补跑及删除处理重建新版本。保留/备份期限和容量尚待实测及批准，不在本设计中承诺无限历史。

普通CHECK只管本行，跨表/无环/集合/匹配语义通过事务内校验和后续适当的约束触发器实现；哪些必须由数据库兜底，在Alembic实施稿中逐条列出。参考[PostgreSQL约束](https://www.postgresql.org/docs/17/ddl-constraints.html)；这不是已经验证了实际PG约束或任务并发。

自动/手动/补跑共用这些版本、任务与覆盖关系；推荐触发方式、幂等检查和未启用边界统一见[架构同步方案](../architecture.md#sync-trigger-policy)，不另建调度定义/队列表。
