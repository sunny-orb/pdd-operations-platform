## 持久化边界

- 保存独立业务输入：店铺和商品链接身份、资料原行及真实链接关系、十类不同粒度的经营事实、目标及实际范围成员。
- 保存必要审计产物：已确认规则包、实际标准/逐项四线、评分聚合特征与分项有效性、报告身份/比较绑定，以及不可变输入、任务和覆盖证据。
- 资料共识、榜单、趋势、漏斗、同比环比、目标达成、诊断、风险、SOP建议、售后完整分组/原因/质量/阶段/排名和中心摘要由固定输入的共享领域服务计算。没有额外摘要、命中、动作工单或通用对象关系表；前端只展示API结果。
- 页面上的运营是来源资料标签，建议岗位不是已指派人员；无真实认领、截止日和处理记录时显示未登记/待安排。当前没有人员管理、统一货品主数据维护、任意指标定义或人工任务闭环，不为它们提前建表。

## 统一字段规范

### 命名、键和约束

| 项目        | 本版统一规则                                                                                                                                                           |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 表/字段     | 英文小写snake_case；一列一含义。原字段以source_前缀或本表明确说明区分规范身份；原分类体系、原款码/SKU/地区不因为同名而跨源等同                                         |
| ID          | 所有本地及来源标识用`TEXT`；本地应用生成稳定字符串，不以店名/商品名作PK；来源ID不转数字、不丢前导零                                                                    |
| PK          | 每张表明确PK；行对象通常id，实际关系/固定指标分项采用明确复合PK；所有PK列非空                                                                                          |
| FK          | 字典`FK → 表.列`为正式外键。未建立分类/款式/地区主表时保留来源标量，不留下悬空的假FK；可空FK不代表可跳过匹配证据                                                       |
| FK删除/更新 | 默认ON DELETE RESTRICT、ON UPDATE NO ACTION；历史已封版输入、被引用实体和报告不级联删除。没有单表自动清理历史或重用来源ID的权限                                        |
| 唯一性      | 接收行`(dataset_version_id, source_row_key)`只防一份交付重复接收，不宣称已经找到业务唯一键。额外业务UQ只对已核粒度设定，未知店铺日/退款/款码粒度不硬设唯一             |
| 可空唯一    | 需要“空也视作同一范围”时明确`NULLS NOT DISTINCT`；可空来源原键不靠普通UQ误判去重。条件UQ、跨表归属和集合完整性分开说明                                                 |
| CHECK       | 非空白代码、有限枚举、金额有限性、成对日期和本行状态形状用CHECK；跨表匹配、无环、集合、完整性证明必须发布事务校验，实施时再落实数据库兜底，不能声称普通CHECK能跨表保证 |
| 默认值      | 不默认业务0、不自动补昨天、负责人、日期或成功状态；本地创建/更新时间按下方自动维护规范，纯并发revision可从0起步。所有其他默认在字段行明确，无说明即调用者显式提供      |

### 类型、时间和空值

| 数据              | 类型及解释                                                                                                                                                    |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 业务日期          | `DATE`，独立起止是含两端闭区间；source真实期间与请求/使用窗口分开。整个交付仅声明一个期间时放版本，不给每一行伪造日期                                         |
| 运行时刻          | `TIMESTAMPTZ`；来源本地时间必须有已核时区依据才可解析，缺依据保原文、解析值NULL。上游修改/创建、实际观察、本地接收、封版、任务成功五种时间分别表达            |
| 金额/源DOUBLE数量 | 有限`NUMERIC`，不预设会截断的精度/scale；显式拒绝NaN/Infinity。人民币元/正式金额最多2位按下方发布验收执行；数量精度和来源元分换算另核，不能从页面显示反推原值 |
| 已核整数计数      | 商品BWD已核整数原计数用`BIGINT`；其他来源DOUBLE计数保`NUMERIC`；样本数/记录数等确为整数才用BIGINT                                                             |
| 比率/增长/倍数    | 有限`NUMERIC`；比例用小数、ROI为倍数，两者不混。按相容范围合计分子分母后相除；分母无效返回NULL及原因，不平均日比率，不擅自限制退款率≤1                        |
| 文本/链接         | `TEXT`；必要原文保持证据，规范空白按冻结解释；外链只存实际可用定位，不存凭据、签名密钥或整行敏感参数                                                          |
| 空值状态          | 真0来自明确源值；字段NULL、无记录、未接收、失败、部分覆盖和不适用分别表达。无已知值合计仍为空，部分已知合计附缺项标记；事实可留未匹配原行，不造规范实体       |
| API边界           | 金额/数量/比率以精确十进制字符串返回，缺失用null并给状态/原因；后端负责正式计算，前端不能以格式化或近似图形值改变业务结果                                     |

<a id="common-field-policy"></a>

### 公共字段的本轮确定规范

以下是技术设计决定；不替代[业务确认登记（剩12项）](../data-contract.md#business-metric-questions)或[M3完成额权威选择](../data-contract.md#m3-completion-branch)。当前ID类型不变，避免仅为统一外观把来源标识改为数值或变更50处FK类型。

| 字段类别         | 类型与统一含义                                                           | 自动维护及边界                                                                                                                                                                                                                     |
| ---------------- | ------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 本地ID及其FK     | 延续TEXT，本地生成不含业务含义的UUID字符串；引用列与被引用列类型完全相同 | 来源店铺/商品/款号/SKU/原记录ID另用TEXT保原值、前导零，不能拿本地ID替代来源业务键；客户端不生成主键含义                                                                                                                            |
| created_at       | TIMESTAMPTZ NOT NULL，数据库DEFAULT transaction_timestamp()              | 本地记录真实创建事件，不等于来源创建、经营日期或实际上架日；首次写入后不允许改写                                                                                                                                                   |
| updated_at       | 可维护实体用TIMESTAMPTZ NOT NULL，初建等于created_at                     | shops/listings采用数据库BEFORE UPDATE触发器：实际业务属性发生变化才更新；使用数据库statement_timestamp()并保证不早于原updated_at/created_at；普通无效重试不刷新，客户端不能指定或伪造                                              |
| 其他本地事件时刻 | received_at/sealed_at及任务登记、开始、结束、租约等均TIMESTAMPTZ         | 由对应受控状态转换自动写入；current_datasets.updated_at只在实际切换成功时写入。没有新增事件不改时间，失败不伪造成功时刻                                                                                                            |
| 来源时刻         | source_created_at/source_updated_at/source_modified_at及观察时刻分别表达 | 仅按来源真值及已核时区解析，不套updated_at自动触发器；来源时间未知保原文/NULL，不能填本地now()                                                                                                                                     |
| 业务日期/期间    | DATE；含两端，必须有真实日期/窗口依据                                    | Asia/Shanghai用于已核当地日语义；不从接收时间、文件名或created_at猜业务日期                                                                                                                                                        |
| 人民币金额原值   | 有限NUMERIC、规范单位元；Decimal计算/API十进制字符串                     | 本轮按用户要求，来源人民币金额原值以数仓为准、最多2位有效小数。仅已核来源金额及其加总金额发布前检查value=trunc(value,2)，1.2300属于2位有效小数；超2位先保必要原值并隔离依赖该值的正式金额发布、补核来源依据，不静默round后冒充原值 |
| 数量、比率与单价 | 已核整数BIGINT；源小数计数、率/ROI/单价/UV价值、标准线用有限NUMERIC      | 比率和参照线保真实精度、按未舍入值汇总/判档，不能统一NUMERIC(20,2)或转分整数；金额显示2位，显示舍入不回写原值                                                                                                                      |
| deleted_at       | 仅shops/listings增加TIMESTAMPTZ NULL，默认NULL                           | 受控软删除事件由数据库时钟赋值，同时status=inactive、更新updated_at；恢复原身份清空deleted_at。其余版本化内容不加通用deleted_at，修订/上游删除通过新版本表达                                                                       |

**金额选择原因。** 以分为单位的BIGINT也能精确表达已核两位金额，但本项目要保留数仓/聚水潭实际精度、负额异常和标准阈值，统一NUMERIC更直接，也避免多源反复乘除100；不并存一套分值和一套元值。正式币种固定CNY/人民币，冻结在来源/版本解释，不给每行再加常量currency。NUMERIC不预设precision/scale，是为了在候选/原始层保留真实证据；二位金额验收发生在正式发布边界。后续如来源正式确认更高有效精度，先更新该字段契约再发布，不能悄降精度。来源DOUBLE已产生的误差不能通过改类型修复，必须按可读原值和来源证据核验。PostgreSQL的定scale NUMERIC会对超scale输入舍入，不能把它当作“拒绝多余小数”的校验；依据见[官方数值类型](https://www.postgresql.org/docs/17/datatype-numeric.html)。

**派生金额与舍入。** 退款超目标测算额、商品预警估算影响等由金额乘率计算的结果，内部使用Decimal及未舍入值比较、排序；中间/派生结果超过2位是正常计算，不套来源金额的两位校验，不误标来源精度异常。最终对外人民币金额值用Decimal按0.01、ROUND_HALF_UP舍入，API返回两位十进制字符串；UI直接格式化该结果，不再近似重算。来源原值不被该显示/输出结果覆盖，原输入和固定公式仍可复算。比率、ROI、单价/UV价值和标准线仍按各自精度契约返回，不因含“元”字就当现金金额截两位。此为本轮技术选择，不新增业务确认项。

**不把时间三件套加到所有30表。** 只有两类可维护身份有created_at/updated_at/deleted_at。原行、事实、目标/标准、评分和报告等内容封版后不原地更新，创建/接收/封版沿dataset_versions和真实任务事件追溯；成员/分项沿父版本取得，不复制整批相同时间。created_at/updated_at本身不能还原每次更改，deleted_at也只能定位软删除事件；真正后台操作须由受控身份、原因和日志留审计证据，不从资料运营标签伪造操作人。事件时钟语义参考[PostgreSQL时间函数](https://www.postgresql.org/docs/17/functions-datetime.html)。

**软删除读取。** 新建/维护选项默认只列deleted_at IS NULL且status=active的身份；历史事实/报告/评分读取原FK，不在公共JOIN中全局排除软删除身份，防止历史金额凭空消失。所有业务UQ继续覆盖软删除行，恢复用原id，不以部分唯一索引放行重复身份；父对象软删除不级联软删事实或另一身份。来源下架标签不自动写deleted_at。当前只设计，不执行删除或后台功能。

### 状态必须按对象分开

统一用TEXT加非空白、有限值CHECK及合法转换校验，不用0/1/2含混代码，也不建一个跨域万能status。各表完整枚举仍由01—04对应字段负责，以下说明边界：

| 负责字段                                        | 含义及允许状态/转换                                                                                                                 | 不应混淆的含义                                                                |
| ----------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| shops/listings.status                           | active启用、inactive停用；软删除要求inactive，恢复后仍由明确操作决定是否启用                                                        | 来源是否开店/上架、数据齐全程度、是否有历史成交                               |
| dataset_versions.state                          | draft候选→validated校验封版→published发布；未通过为rejected，不作为当前；修正新建版本                                               | published不是已证明全店齐数；不再当前不等于删除/拒绝                          |
| task_runs.status                                | queued登记、running执行、succeeded成功、failed失败、cancelled取消、abandoned租约失效后受控接管；终态不原地重跑                      | 任务成功不是来源完整；重试是新尝试，失败不更新成功水位                        |
| 匹配/date/relationship/日期适用状态             | 事实匹配、日期解析、资料关系成立及逐链接日期适用各用本字段枚举                                                                      | 已解析日期不等于已核业务归属；未匹配不等于缺记录；not_applicable不等于unknown |
| coverage_records两类state                       | availability区分observed/no_records/not_received/field_null/not_applicable；completeness区分unknown/partial/complete/not_applicable | 有记录不等于完整；无记录不自动等于0，失败由任务另行表达                       |
| signal_status、标准/规则确认状态、decision_code | 输入有效、标准线可用、规则确认/证据状态和建议分支分别表达；见03闭合集合                                                             | valid不等于已业务验收，建议不是已执行，观察不算已证异常                       |
| source_*原状态及原标签                          | 按来源保留原值/NULL；与本项目有限状态分列                                                                                           | 不从来源删除标签推定可以删除本地历史，不把未知映射为成功                      |

### JSON的有限使用

JSON只允许以下三类有冻结结构的文档值，均需schema修订、键白名单/类型校验；不得塞正式实体关联、目标名单、经营指标EAV或复制显式列。

1. `return_records.source_analysis_fields`：售后分类器确实读取、且没有显式列的必要额外原文本投影；只允许冻结键、原文本或NULL。实际配置未核时保留待验状态，不臆造备注等键，也不丢全量原因输入。
2. `product_score_items.evidence_context`：封闭的角色/字段码、真实缺失日期和必要说明，精确键/类型见03；不复制数值、权重、阈值或对象FK。
3. `rule_sets.parameters`：当前v1各业务域的有限结构，包含已核权重、门槛、词典/模板及启用门控，键/代码/单位/NULL与跨码引用逐项在03定义。未知实际词典/算法或13项未决分支保持禁用及证据状态，不建设任意规则DSL。

资料原格保留，解析诊断按关系版固定的解释/代码重放；不再保存完整词元JSON，也不为纯映射调整复制原行。逐链接日期适用性是正式关系属性，保存于profile_listing_links的两列中，日期值不重复。

### 范式与审计保存

- **第一范式：**正式店铺/链接/目标成员各自一行，实际N:M使用关系表；资料原格中的多ID文本是不可改写的来源证据，正式关系已经拆出，不能拿逗号列表直接JOIN。
- **第二范式：**关系表非键属性依赖完整关系键。目标值只在目标头，权重只在固定规则包，四线只在标准分项，不随成员、评分分项重复保存。
- **第三范式：**链接确定店铺，商品事实/评分不再重复规范shop_id；任务从结果版本追溯固定配置，输入关系不再复制来源/数据集/规则；报告头不保存可从完整固定输入重算的Q/A/S/P和多层汇总。
- **来源证据与计算输入：**原店铺/商品名及source原键描述交付本身，允许与已核规范身份并存；原值冲突不是自动用规范名覆盖。来源时刻原文与解析值的并存用于解释失败审计。
- **唯一需要持久化的计算特征：**product_scores的13个实际聚合特征是该次评分可追溯的输入产物，权威为所绑版本/窗口及冻结算法；封版时逐项复算校验，封版后不单独更新。分项仅保存有效性/原因，当前值、档位、得分、总分即时派生。保存目的为审计，不是未经实测的查询性能优化。

本版没有为推测性能新增反范式汇总/宽表或物化视图。将来如果实测需要物化，须先记录慢查询/容量、权威输入、刷新与失效机制、复算校验，再单独变更设计。

## 五页查询与索引设计（真实查询性能待验收）

目标是让常用查询先固定版本，再缩小实际店铺/链接和日期范围，稳定分页；不把加索引数量当性能保证。索引、SQL、数据规模、并发和统计信息一起决定速度；本轮没有真实PG压测结果，不宣称已达到某个响应时限。前期无Redis，后续仅按架构中的实测条件评估。

PK/UQ会建立对应索引，不能再建同列同序普通索引；FK的引用端不会自动获得索引，按实际查找/更新检查需求补充。下面均为**普通B-tree候选**，无UNIQUE者不改变业务唯一性；已有PK/UQ定义仍在各表字典，不在此另抄一份。凡写“无”表示先复用已有索引，而非漏设计。[官方约束与索引说明](https://www.postgresql.org/docs/17/ddl-constraints.html)及[多列索引规则](https://www.postgresql.org/docs/17/indexes-multicolumn.html)是技术依据。

**FK与删除检查。** links.shop_id及高频输入反查已补索引；其他大事实的实体FK不一律机械增建单列索引。日常查询携带固定dataset_version_id，优先复用版本+实体条件UQ/上述范围索引；已发布父对象禁止硬删除，父软删除不发起逐事实FK更新。实施时对未覆盖的反向引用、实际管理排障SQL和锁检查测量，确需时补以FK列为首的索引，不重复声称版本首列索引能覆盖任意不带版本的FK查找。

**查询执行约束。** 事实各自先聚合，资料先作每链接唯一共识，再关联，避免一对多放大；同请求复用相同范围结果，后端返回图表聚合点和分页明细，不把全量事实送前端。日明细采用固定版本下(business_date,listing_id,id)的升序、NULLS LAST确定顺序；含NULL键的诊断集合游标显式区分空值段，不用含NULL的裸元组比较跳漏行；深分页用同一完整排序键的游标，避免无界OFFSET。评分按派生总分排序无法靠原事实索引直接加速，先在固定结果版关联十项后一次计算/排序，再分页；仅在实测需要时按已批准规则物化，不为此重复存分数。

**有条件再加的索引。** 中文名称/原因“包含”搜索若实测慢，考虑pg_trgm GIN并逐列指定真实需要的文本，不启用整行JSON GIN；先对固定版本/范围过滤。资料共识名不等于某个原行名，候选过滤后仍须按正式共识/回退规则复核，不能用原文本预筛删掉应保留的经营事实。表达式/部分索引的查询须匹配其表达式/谓词，跨任意字段搜索不得假定普通B-tree有效；不先加GIN/BRIN/分区或大INCLUDE金额宽索引。

**实施验收。** 批量发布后维护ANALYZE统计，按五页真实查询和声明的数据量/并发，用EXPLAIN (ANALYZE, BUFFERS)核对扫描范围、估算/实际行数、排序/临时落盘、返回量与耗时，并测同步写入和索引体积；索引构建/回退方式随Alembic实施计划评审。全范围聚合仍需读取实际输入，索引不能把它变成零成本。未达到批准的响应目标继续优化SQL/索引/分页，必要物化另行说明刷新/失效，不以Redis遮住不合理查询。本轮没有运行这些SQL或安装扩展。

## 来源、版本和关联不放大事实

资料查询采用derived `profile_links`版沿唯一`version_inputs.input_role=profile_records`固定一份source原行版；对某链接的全部有效关系逐字段求唯一非空共识，冲突保留来源候选，不取第一/最后一行。资料投影每链接最多一行，以LEFT JOIN补展示，不丢缺资料的经营事实。当前资料归属与历史当时归属按契约区分。日期按每条原行—链接关系的适用状态/证据核验，未知/冲突不会被一条好日期掩盖；名称按01所定实际固定事实/窗口内规则回退，不能取任意首末行。

商品日、店铺日、商品推广、店铺渠道、店铺退款、两类地区及J1/J2/J3均按真实粒度各自聚合后组合。退款与成交按已核店铺/日期匹配；资料多行、推广多行和不同期间售后行不能直接明细互JOIN后SUM。相同款码只有命名空间及范围相容才可归组，不设置猜测订单或跨源SKU外键。售后各层完整组键、销售分母唯一归属/失败返回及跨期配对以[02](02-business-facts.md#aftersales-group-matching)为唯一设计正文；粗销售块不能复制给多个细售后组，零退货销售组仍在相容分母总体内。

一逻辑数据集一份当前生效版本；店铺概览和明星店铺是不同业务范围，分别用`shop_channel_product_promotion`、`shop_channel_star_shop`选择版本，共用同一事实表，分别汇总后按已确认渠道规则组合。切源先对账，不自动混源/回退。旧补齐记录如作为页面说明保留，读取对应历史必要事实版并与当前源范围比较，逐条给出实际来源、生效/已替换/范围外状态，不能将历史说明重新加进当前金额。各源更新时间、业务最新日、已核完整日和本地成功时间分别返回。有关发布、重试、水位、覆盖及一致读的完整规范见[04](04-versioning.md)。

售后报告按固定完整输入重算全量分组/原因/质量/尺码/阶段；Top只在展示时截取。J1确认期与J2/J3支付期即使同日也不是同批订单。历史报告、近8期Q趋势、同类型上期/去年和修订比较沿固定报告身份/输入读取；期间列表/趋势先按逻辑期间选有效修订，同期间旧修订不作为上期；替换当前入口不使历史版本失效，不用新回补悄改旧报告比较绑定。

### 即时查询也固定规则修订

不保存结果的商品风险/健康度、推广SOP及运营中心查询，由受版本管理的部署配置按domain指定明确的不可变`rule_sets.id`，并固定实际领域计算代码修订；不按`max(revision)`、最大确认时间或读取顺序找“最新包”。入口核验包ID存在、domain相符、结构相容且实际运行分支已确认；缺包/未确认时给规则不可用或待验证状态，不能输出正式判断。

一次响应固定“数据版本＋规则包ID＋领域代码修订＋解释/配置修订”的向量，分页、详情和跨区块复用这一向量；其中任何组成改变，按契约返回版本失效并整组重取。部署配置仅指定有限用途的实际ID及修订，不另建规则当前指针平台。评分与历史报告等保存产物继续只按其版本FK/输入固定规则，不能被当前配置改写。
