# 月度 GMV 预测的日报输入

预测采用拼多多销售日报 F01 的「销售收入（GMV）」原值，单位元。已核实该公式为「统计金额－做单金额」。店铺销售页的经营金额继续读取数仓发布的店铺成交原值。两个指标使用同一批六店身份，各自保留其业务定义。[来源与口径](../data-contract.md#23-飞书五表与现成公式)

## 数据结构与更新

现有 `shop_refund_records` 已按 F01 的来源记录保留日期、平台、部门、店铺、统计金额和退款。一个不可变 `dataset_versions` 对应多条 F01 记录，每条沿用原有来源键和店铺外键。在同一原行上添加两个可空的有限 `NUMERIC` 字段，均无默认值。

| 字段                       | 飞书字段                      | 用途                                                               |
| -------------------------- | ----------------------------- | ------------------------------------------------------------------ |
| `source_reported_gmv`      | 销售收入（GMV），`fldax7fYxe` | 保存源公式的数值。预测只累计基础金额存在且公式核对一致的日报原值。 |
| `source_adjustment_amount` | 做单金额，`fldQmlTprE`        | 保存来源数值和空白状态，用于核对公式。销售收入只计一次。           |

调度及手工命令在读取 F01 前检查目标库中的两列。修订 22 在原分页和双读中一并接收 GMV 和做单金额。公司现行修订 20 沿用七字段的退款接收、归档和版本指纹。两列只存在其一时报告结构异常。两种投影都保存原始表示、字段映射和飞书修订号。业务范围沿用已批准的拼多多市场部六店和财年窗口。内容有修订时按既有流程归档并发布完整新版本。旧键消失、分页未完成或来源修订改变沿用原有拒绝/重试机制。既有归档使用对应解释器重放。

## 读取和校验

一次问答固定 PostgreSQL 只读可重复读快照中的 F01 和平台月目标版本。利用现有 `(dataset_version_id,business_date,shop_id,id)` 索引，只查一个自然月截至上海昨日的六店原行。每店每日报表须恰一条，基础金额、来源 GMV 均非空且非负，且与来源做单字段可核对。基础金额为空时，即使公式显示 0 也列缺项；明确的基础及公式零可累计。只用月首起连续通过核对的日子，首个缺口后的记录保留覆盖说明。日报逐店核对截至和上游声明完整日分别记录。

月目标限已发布的原版拼多多月 GMV、该月份和与六店完全相同的成员，每月只取一次。推广的来源口径未证实前保留缺项。请求只读本地，沿用原有索引和数据库连接，无单独缓存或上游调用。

## 迁移、恢复与验收

在 `20261127_21` 后追加 Alembic `20261127_22`。先核对本机迁移起点，保存同集群结构、授权和受影响的 F01 原行备份，再在项目同步锁下升级并核对经营指针。升级后按既有流程接收 F01。旧事实的两列保持 NULL；已发布记录、退款版本、历史输入及其他经营来源继续保留。原三类历史离线归档未包含 F01，地区重建解释不变。新投影已发布或新列已有数据时拒绝删除列的降级，可保留结构回退读取代码，并继续使用已封存原投影恢复。生产单独按部署授权和备份安排执行。

隔离 PostgreSQL 验收应覆盖旧版与新版归档重放、同店日重复、缺店、空基础与真实零、当前日排除、月目标缺失与冲突、并发切版时同一查询快照稳定。业务核对把来源日报、销售看板及 SOP 历史算例按相同店铺与日期对齐并分别列示结果。
