# 月度 GMV 预测知识和运行记录

指定飞书文档由香草维护。正式预测提问触发本地任务按修订接收原文并核验规则。问答服务只读核验回执对应的 PostgreSQL 版本与真实运行记录。普通做法类文档不写入预测表。21 引入知识与快照对象，23 在 22 之后扩充当前版本视图。[飞书原文](https://kocotree.feishu.cn/docx/H3svdLyEYoxsK3xgeBOceOxfnMc)

## 对象、关联与字段

| 对象                         | 粒度、字段与约束                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `forecast_sop_source`        | 一篇批准文档一行。`document_id` 为文本主键，`source_url` 为原文入口，正式来源限定本篇。随机本机隔离库可显式指定获准测试副本，每库仍只登记一篇。`revision` 为最近观察到的最高正整数修订。`version_revision` 可空，外键指向同一篇的版本。`state` 为待同步、就绪、暂时未核或已撤下，`reason` 为可公开的原因码。`checked_at` 记尝试时刻，`verified_at` 记最近成功核对可引用版本的时刻。                                                                |
| `forecast_sop_versions`      | 文档与修订为复合主键，文档外键指向来源，构成 1:N。`content` 保留该次完整 Markdown 含表格，`content_sha256` 为 UTF-8 原文摘要。`rule` 冻结同版核验结果。通过时保存受控规则、条款依据及 `interpretation` 的版本、方法和模型名。业务冲突或超出计算能力时保存 `status=rejected` 与 `issues`，每项含原因和同版章节、摘句。历史空值表示当时无法编译。`synced_at` 记该版首次接收时刻。运行账号只能追加修订。                                              |
| `forecast_monthly_snapshots` | 每个预测月份和实际输入指纹一行，复合主键为 `month` 和 `input_version`。`cutoff` 为当次经营截止日，`payload` 保存当期实际、目标、日预测、中心预测、规则修订、范围版本及聚合依据。`previous_input_version` 在首次记录时选取，通过同月自引用外键固定当时用于比较的实际运行。`document_id`、`rule_revision` 共同引用当次使用的 SOP 修订。`created_at` 为数据库记录时刻。按同月及截止日筛选可比较记录，取实际记录时刻最近的一次；同键重跑复用首次记录。 |
| `read_forecast_sop`          | 来源与当前修订的只读投影。可执行时返回同版原文及规则，拒绝时返回 `unsupported`、空规则及本版 `issues`。过期、已撤下或待同步时，原文、规则及引文均不可读取。最后成功核对后 24 小时为本机容错期限。                                                                                                                                                                                                                                                  |

来源信息、探测状态、不可变修订和每月冻结输出各依赖自身业务键。原文与同版规则一同发布，同一次业务运行只落一个输入指纹；月份头为月初，所有时刻为 `timestamptz`。使用现有 PostgreSQL，无跨请求缓存。知识版本独立于经营事实及其归档。API 角色仅可查询当前视图和真实预测快照，任务角色可写来源状态、追加版本与预测快照。

## 升级、运行和恢复

1. 在隔离 PostgreSQL 17 从 20 升到 21，事务只建三表、一视图、索引和运行权限。初始化不带正文、凭据或合成预测。离线重新生成本机完整 SQL；公司单账号交付目标仍固定 20。
2. 正式预测或规则提问时，独立任务读取固定文档的元数据，修订改变时立即撤下旧指针。钉住新修订读取全文，校验原文和规则后再次探测。两次修订相符才在同一事务写版本及当前指针。重叠任务不重复抓取；较旧的元数据和读途中再次修改均不能恢复旧规则。
3. 撤权或删除立即撤下当前入口。若恢复访问的是已接收的修订，重读全文、核对同版摘要和最新修订，再恢复首次核验的结果。同一修订出现不同正文时继续待同步。尚未发现新版时的短暂探测故障保留已核版本及实际时刻。发现新版后即停用旧版，模型超时等临时失败留待下次重试。拒绝结果在该修订内冻结，后续编辑进入新的核验。本次无法确认修订时不出正式金额。经营建议单独按提问选取文档原文。
4. 日快照只在当天已有正式提问成功核验规则后检查本地输入，并保留该核验时刻。定时任务不访问飞书或调用模型，在同一事务保存稳定输入的一份结果。新快照绑定规则行并使用月份锁串行绑定前次；当可重复读事务看不到已成功提交的新输入或运行时，整笔重试。前次比较限于经营截止日不晚于本次的真实记录。问答不生成或保存运行记录。
5. 23 使用 PostgreSQL 原有文档 1:N 修订、修订 1:N 预测运行的两个关系和原有主键、外键、索引。事务只修改视图和同版结果的字段说明，增加一个只读 JSON 引文投影。旧正文、旧版合法规则、历史快照及经营归档保留，已按新方法核验的版本只读持久化结果。测试覆盖原地 22→23、空库安装、撤权与过期、并发、重试、历史数据兼容和归档恢复指纹。
6. 本机升级前核对实际起点、备份及可恢复性，暂停知识与预测任务，按 20→21→22→23 的相应增量执行，复核当前视图与公开权限后恢复任务。23→22 只允许尚未写入新方法结果的库，恢复旧视图及原有权限、说明。21→20 只允许知识和运行表均为空。已有新结果时采用前向修复或经批准的备份恢复。

元数据及错误码定义见[飞书获取文档基本信息](https://open.feishu.cn/document/server-docs/docs/docs/docx-v1/document/get.md)。

## 生产发布

现有公司库按 20 → 21 → 22 → 23 的顺序，在固定项目维护入口的同一事务升级。暂停唯一同步进程后获取项目与领域锁，比较相容目录、权限、RPA、发布指针和历史报告。迁移只建知识对象、增加可空 F01 字段并扩展只读视图。保留已有版本和归档。升级后由同步进程按原 F01 接收流程发布新增投影，再开放预测。

飞书机器人继续在已有同步容器内运行。问答服务通过项目私有网络和独立服务令牌，按登记键读取特定文档，或核验正式预测规则。问答容器只从数据库读本次核验的版本。运营修改飞书后，相关提问才触发修订核对；同版规则不重复送模型。快照请求由同步容器记录，继续走已有调度。

验收包括真实隔离 PostgreSQL 增量、审批对象和业务历史保持、生产机器人读取固定文档、F01 六店逐日覆盖、重复预测一致与浏览器依据。故障恢复先停用知识服务入口，再按原流程回退应用镜像。已发布后保留 23 结构及新增数据，禁止重放空库脚本或自动删除字段。
