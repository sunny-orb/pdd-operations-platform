## Review Focus

1. 旧M1迁移被误执行：新基线独立根目录/独立版本表，不接旧head，不导入旧模型或设置。
2. 494字段或50个FK漂移：离线测试逐列比较四组字典及冻结元数据，不只比较总数。
3. 软删除丢历史/重复身份：保留业务唯一键和RESTRICT外键，时间触发器只作用两类身份。
4. 原始异常被清洗成假值：无业务0/日期/身份默认，不截NUMERIC scale，不把来源删除标签当本地删除。
5. 回退误删业务数据：downgrade拒绝含数据的项目表，不CASCADE；真实回退/并发/约束在隔离PG验证，结果见validation。

### 对象、关系与字段复核

- 01—04字典逐列对应冻结元数据：4/10/11/5张表、39/239/151/65字段，总30表494字段；类型、可空、PK、50处FK及494个中文列注释逐项一致。主表/关系表/事实/结果/版本职责不混入旧72表或M1迁移。
- 50个FK均TEXT同型，RESTRICT/NO ACTION；非自引用依赖无环，建表可依赖排序，回退可逆序。资料原行↔链接及目标↔店铺通过关系表表达N:M；标准/评分十项是头1:N分项，数据版本1:N内容，输入血缘N:M。报告当前入口依用途选择一份版本，不新增完成额表。
- M3-01=A继续复用店铺日成交；金额不使用浮点、不设截断scale、不默认0，65个NUMERIC列均拒绝NaN/±Infinity；正式来源金额两位验收仍由未来发布器按已核单位执行。
- 仅shops/listings软删除，自动维护本地创建/更新时间；链接业务身份不迁移、软删除不释放业务唯一键，不硬删历史关联。事实/审计产物不机械增加updated_at/deleted_at。

### 范式与必要留存

1NF：正式身份、关系和成员单行单对象；资料多ID原格仅为不可改写的来源证据，正式关联已拆行。JSON只用于有限规则参数、缺项解释及必要来源扩展，不能成为另一套任意实体表。关系查询不直接JOIN原格列表。

2NF：目标数值依赖目标头，不随范围成员重复；标准四线依赖标准＋指标；评分状态依赖评分＋指标；输入窗口依赖输出＋角色。复合键属性没有只依赖其中一列的业务数据。

3NF：链接确定店铺，商品事实不重复规范shop_id；版本级来源/规则/时间沿FK读取；任务不复制结果配置，报告不缓存Q/A/S/P多层合计。来源观察名/原文与规范主数据是不同事实。13项评分聚合特征、固定规则/输出分支为历史审计与复算留存，原因已在03字典说明，不是为假设性能建立总分/摘要宽表。本轮未增加性能反范式表、物化视图或Redis。
