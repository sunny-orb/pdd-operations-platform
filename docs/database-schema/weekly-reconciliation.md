# 每周数仓对账状态

对象是一个固定范围数仓来源的当前对账周期和最近成功时间。每个来源至多一行，主键为既有来源清单中的字符串ID，与普通检查点通过同一来源ID逻辑一对一。首次登记可能早于普通检查，二者无外键。首次尝试可引用一个既有普通任务，同一历史组合任务可对应多个来源。对账与发布版本没有直接外键，对账可验证已发布内容而不生成新版本。经营事实、指标、归档输入和发布依赖沿现有模型。

主库继续使用PostgreSQL，状态以短事务读取和写入，不引入缓存。应用在后台调度持有既有项目会话锁时写表，API在只读一致快照读取。主键索引即可，最多9行。所有时间为TIMESTAMPTZ，周期按北京时间定义。

| 字段             | 类型与约束                              | 含义                                                                                             |
| ---------------- | --------------------------------------- | ------------------------------------------------------------------------------------------------ |
| source_id        | TEXT，PK，原八来源＋product_regions     | 对账物理来源                                                                                     |
| cycle_at         | TIMESTAMPTZ，非空                       | 已登记周期的计划起点                                                                             |
| status           | TEXT，非空                              | waiting／running／failed／deferred／succeeded                                                    |
| last_attempt_at  | TIMESTAMPTZ，可空                       | 最近对账尝试开始，未运行时为空                                                                   |
| last_finished_at | TIMESTAMPTZ，可空                       | 本次尝试结束，等待或运行时为空                                                                   |
| last_success_at  | TIMESTAMPTZ，可空                       | 最近完成的成功对账，失败、延后或重试不推进                                                       |
| legacy_task_id   | TEXT，可空，FK → task_runs.id，删除置空 | 首次对账前已存在的普通任务回退证据，首次采集后固定；无旧任务留空                                 |
| error_code       | TEXT，可空，固定枚举                    | 接收失败、前后标记变化或读取失败、工作中断、维护延后或历史恢复要求；重试中保留尚未解决的前次原因 |

一行描述一个来源，每个非键字段直接依赖来源键。下次重试从失败或延后的结束时刻加配置间隔推导，下一周期从成功结束之后的首个周日时点推导，无冗余的重试计数、派生时间、业务数据或上游身份信息。

## 调度和事务

- 首次自动轮询登记即将到来的周日17:00，周日当天已经到点时登记当天周期。登记后停机跨日也能恢复到期周期。升级不补造历史对账记录。手动强制接收不登记或消费自动周期。
- 已有失败或延后的周期沿用原起点，至少等本次尝试结束后300秒才重试。重复失败无次数上限，跨周继续同一周期。成功即关闭周期，下一次在完成时间之后的首个周日17:00。时间配置见 `config/sync.toml`。
- 调度持有 `project-source-sync` 会话锁，阻止其他调度、手动接收或维护并发读写同一范围。锁内短事务登记或开始尝试，执行获准范围读取、校验和必要发布后，以短事务结算结果。重新取得锁时发现上轮仍运行，确认上轮执行者已失去该锁，将其记为中断，以发现时刻为保守结束时刻，等待重试间隔。若发布已提交而状态结算中断，后续重读由既有发布器按内容幂等处理。
- 首次开始前冻结已有普通任务引用。普通检查点一旦有实际接收结果即优先使用。旧普通接收失败在下一普通时点继续受控重试，稳定接收成功后关闭。既有已发布数据、旧失败及其时刻可同时保留；周对账重试不把自己的发布任务写成旧普通证据。
- 普通检查与对账同轮需要下载时共用一次范围接收及前后标记确认，分别保存结果。对账成功要求接收校验成功且前后标记可读并相同，派生失败按原规则另记。对账单独失败或因维护延后只写对账结果，保留普通接收和检查证据。对账单独成功可记录稳定的接受标记，只有确认解决普通失败所对应的同一变化时才关闭该失败。接受标记与对账成功在同一事务写入。普通接收结束时间晚于最近接受时间时，下一普通检查继续复验，即使标记已回到上次接受值。
- API返回已登记周期、状态、开始／结束／成功时间、可计算的下次重试及计划时点。前端单独显示对账情况及既有数据可用性。结构化日志只记录固定来源、周期、状态、时刻和安全错误码。

## 迁移、权限和验收

Alembic15追加 `source_reconciliations`，不修改历史revision。无存量回填，不触碰事实或版本。沿生成器更新本机及单账号空库SQL，既有库暂停任务与维护后走增量迁移，迁移同样取得项目互斥锁。表字段与保留维护、备份恢复的对象清单同步。归档回执继续绑定精确结构头，数据库守卫只切换认可的head。若已有离线版本，先用原版本恢复后再升级；降级同样保留15生成的归档记录。API角色只授予SELECT，接收角色授予SELECT／INSERT／UPDATE；单账号部署沿现有权限。应用回退优先保留新表。降级先锁表，存在状态记录则拒绝删除；修复追加迁移，不自动清空历史运行证据。

在随机本机PG验证升级、权限、时间和状态约束、空表降级、带记录拒绝降级、重启续跑、互斥、独立失败和只读接口。上游输入用受控合成边界，实际数仓接收与生产部署另按授权验收。
