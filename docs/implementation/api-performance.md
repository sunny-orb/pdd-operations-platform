## 第二轮：商品与售后首次查询

用户要求继续压低约两秒的商品/售后响应，且准确性和展示数据不变。第二轮开始前单独保留当前工作区模块作为基线，不以更早的Git HEAD代替；相同日期/报告各5次：商品总览1783.62ms、售后总览1921.84ms、售后分析1576.35ms。私有证据在`var/audits/performance-round2/`。

### 商品

同一窗口的七个指标反复构造商品—日期配对；总览、日趋势和7/14/30日窗口反复汇总相同原行；热榜每款只消费金额和买家转化，却计算全部指标。

1. `comparisons` 每对窗口只构造一次身份与日期集合，金额、访客、收藏、买家、件数及比率仍独立检查必需字段。日历覆盖、完整K、闰日无映射、负值/缺值阻断不变。
2. 一个请求内计算日聚合，`merge_aggregates` 累加精确原值、有效/观察行数、成对分子和分母，再计算比率；不平均日比率，不以单字段有效行替代成对有效行。原行仍用于覆盖门禁，缺失、真实零、无记录及非正分母分别表达。
3. 分组合并前，从原始金额最大整数位/小数位、行数进位空间及BIGINT计数19位上界判定精度包络。可能超出50位时，所有窗口及去年窗口回原行、原顺序聚合；不从已经抵消的日小计判断安全，连 `0E+21` 这样的原Decimal字符串表示也保持兼容。
4. 热榜只计算其消费的金额和转化率，前7日只取精确金额。默认聚合完整输出及其他调用方不变。
5. 商品/新品目录只消费所选日期内的身份与名称，改用六字段的专用读取，不再拉取全60天经营数字并创建无用分组。排序仍按原日期、店铺、商品、来源行键；资料共识、最近非空名称回退、联动筛选、选中回显、搜索及分页不变。普通经营读取和推广/评分生产链不改。

### 售后

查询时在PostgreSQL内分别按完整九字段身份压缩三角色；J1另按原原因和售后分类分组。只减少SQL向程序传输的重复身份，不JOIN原事实、不删原行贡献，也不新增持久化汇总表。

- 九身份字段不转空、不归一；筛选先选择完整对象，随后保留该对象全部原因和销售分母。
- Q/A/S/P/销售数量逐字段 `COUNT(field)=COUNT(*)` 才给完整SUM；任何NULL仍使完整值不可用。每组保留原行数、金额已知/空/零行数及已知小计。记录卡、覆盖、缺原因数、尺码冲突数按原行数统计。
- 保留最小 `source_row_key` 并按其排序，保持原示例行和排序；期间MIN/MAX来自原行。300,000行保护仍按原行总数检查，不能按压缩后的组数绕过。
- NUMERIC无位数上限。每字段读取 `SUM(ABS(field))`，保留抵消前幅度和最大scale，再按组数保守计算进位；只有证明全部原行及任意子集可在既有50位内精确相加时才压缩，否则该角色回原行、原排序及原算法。安全路径才复用请求内摘要；不安全路径的历史/元信息保持原独立SQL精确SUM。
- 去掉数值分组中未被消费的重复分类计算；实际卡片、原因和分析表仍计算完整分类。缺销售分类的全范围检查只算一次，分母门禁和拒收全窗门禁不变。
- 默认八期趋势只消费实退数量Q，因此每期仅读J1汇总。保留全部八期、顺序及NULL；其他历史分析仍用所需三角色，当前报告动态元信息照常读取三源。

全部复用仅存在一次固定版本的只读事务内，没有跨请求旧结果缓存；来源、数据库对象/字段/约束、同步和发布流程不变，不需新迁移。金额保持Decimal/NUMERIC，不使用采样、删行、改变小数精度或隐藏展示内容。

验收必须包含同一只读快照内完整响应差分、NULL/真实零/缺角色/重复与冲突对象反例、真实PG集成、受共享计算影响的推广回归；最后按同一窗口复测API并核验商品和售后页面。源码定义版本更新和动态同步状态单独处理，不误当金额变化。
