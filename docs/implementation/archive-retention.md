# 采集归档去重、容量与离线保留

2026-11-09 用户批准：修复重复落盘；服务器保留当前及上一成功版本和依赖；历史原始输入转存本地并校验后清理；容量不足失败保旧。数据库经营事实、已发布版本和来源权限不改变。

## 实施边界与顺序

1. 原始输入按既有业务指纹先判断复用，再落盘。复用必须核实被引用归档完整；已离线的旧版本不得静默重新成为current。不可从当前单源候选拼造旧的多源批次。
2. 原始文件写入通过统一私有写入入口；配置归档容量上限、磁盘保留和告警阈值，超限拒绝新增写入，保留原current。外部来源临时文件在来源调用结束后删除；容量检查覆盖接收入口，未知增长失败关闭，不删除唯一输入腾空间。
3. 保留当前及上一成功版本，对version_inputs递归闭包；目录型retained_input_ref保留整批，所有任务解释/校验证据保留。上一版从真实发布任务和运行状态判断，历史序列不足时多保留候选。刚生成/仍运行的目录不清理。
4. 离线清理生成逐文件清单与SHA256，压缩流下载到本机私有目录并逐文件验证；本机校验成功后才允许按同一清单逐项移除原始payload。维护全局同步锁与本项目发布锁，重新比对current、依赖、路径、inode/mtime/摘要，拒绝符号链接和硬链接；记录本地归档位置与恢复清单。没有离线确认的唯一输入不得自动删除。
5. 提供受控恢复入口，将经摘要验证的指定历史批次恢复到原路径，不改数据库指针。已离线版本再次命中指纹时，明确报ARCHIVE_RESTORE_REQUIRED并保旧，不能宣称同步成功。
6. 自动维护只清理可证明重复/本任务临时数据、已校验转存且不受保护的历史payload；独一份历史随时间增多时受容量上限约束，不承诺无限留存。告警写结构化运维状态和Worker日志，不向他人发送消息。

- 文件边界：超容量/磁盘保留、链接、目录越界、内容变化、写入失败均不损伤已存在文件。

## 运维命令与默认参数

默认每个归档根目录12GiB硬上限、8GiB起日志告警、所在文件系统至少2GiB余量。飞书CLI子进程单输出文件64MiB限制，调用前为数据/清单预留128MiB；临时页在成功或异常结束时清理。本机测试只使用127.0.0.1:55432随机隔离PG，绝不迁移公司库。

`python scripts/archive-maintenance.py plan`只读列出保护版本、批次与候选。将计划保存为本项目私有文件后，`export --plan <计划>`向stdout输出gzip tar流，应直接传输到本机权限700目录内的600文件，不在服务器再复制一份大归档。`verify --bundle <本地包>`逐文件验证并输出回执（items、verified、压缩包SHA256、本机绝对路径）；本机验证完成才将回执传回项目私有目录并执行`apply --plan <计划> --receipt <回执>`。apply在所有现行发布锁和归档文件锁下重算保护、核验原始摘要，先持久保存回执再逐项删除，完整保留任务/解释/生产者/校验证据。计划失效、同步忙或源文件变化均拒绝删除。

历史原始输入依然被封版数据库元数据引用；离线回执是其物理位置记录，不能为清理改写封版行。恢复时把经验证的包放回项目私有维护目录，`restore --bundle <包>`先验证整个包，再流式原样恢复缺失文件；相同已有文件跳过，差异拒绝覆盖，不改current。旧离线指纹再次出现时要求先恢复；API继续提供原已成功版本。

自动同步负责去重、当前接收临时页清理和容量拒绝；唯一历史输入的离线转存/删除由以上显式维护流程执行。用户本机不可假定永久在线，未收到离线校验回执的新历史输入继续保留，达到容量上限时同步失败保旧，不能伪称已配置持续异地备份。未知、孤立及失败批次原始输入本轮保守保留，不以文件名判断可删。
