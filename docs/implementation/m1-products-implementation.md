## 设计与约束

### 运营中心商品风险出口（2026-11-03）

按用户决定先沿现有线上日度规则提供真实结果，SOP完善后续进行。增加`GET /api/v1/products/risks`，请求固定版本和与商品页相同的日期/筛选；返回完整名单、原有来源P级/排序、数值、期间和评估数量，不截前三。接口字段及接入步骤由[data-contract](../data-contract.md#product-risk-api)统一维护。

将风险收集和排序收敛到`query.collect_risks`，页面和专用出口共用；八日必需字段判断集中在`metrics.risk_window_ready`。专用接口不计算七卡、同比、趋势大图或评分；沿既有只读RR快照、版本指纹和空值语义。无新表、迁移、同步或第三方请求；不修改运营中心消费代码。先写真实PG协议回归，再核实际发布数据与修改前页面/评分一致，完成检查、测试、构建和独立审查。SOP规则与真实业务准确率仍是后续验收范围。

### 线上评分复用：名单与摘要（2026-11-02）

用户要求验证后复用线上规则，不再沿用开发自建标准。模型原件核查由m1-model-reuse维护；参数未齐不得重训替代或把旧结果当新日期结果。名单与计数先按已明确规则修复。

对象为当前资料明确标新品的店铺商品链接；profile_listing_links固定资料版本，按listing_id收敛后，从listings/shops主键取得身份，商品日事实为可无记录的1:N输入。只为评分补齐无事实链接，总览及明细保持原事实范围。复用PostgreSQL与既有表，不加表、索引、缓存或迁移；只读快照固定版本，删除、更新及发布约束沿用。

实施：评分列表和评分筛选共用完整新品目录；无事实保留未评分卡及空值。新增total_count、scored_count作为全范围摘要，total继续为筛后分页总数；同线上已计算数按筛选前全集统计，部分计分计入。前端显示“筛后数 / 全部数”，日期取实际评分窗口。真实PG覆盖无事实、跨店同ID、资料重复/等级冲突、筛选、分页及详情；真实API逐款对比已有评分、总览及明细；检查、测试、构建及浏览器核验后更新业务文档。

业务对象为完整店铺商品链接、当前资料、商品日事实、商品日推广、标准和评分。使用PostgreSQL既有30表，无新缓存服务。listings与日事实1:N，资料与链接N:M由profile_listing_links表达。先逐链接逐字段形成唯一共识，再LEFT JOIN事实；资料冲突不取首末行，不放大金额。商品与推广各自汇总，禁止明细JOIN相乘。

现有字段、索引满足范围；追加Alembic04仅授予已有表最小运行权限，不改冻结基线。ID/TEXT、金额NUMERIC/Decimal、API数值字符串；缺失与零分开。保留原行键和必要原格，上架日期适用性未知不造日期。接收三张已授权数仓表：商品/推广取六店day的当前60个日历日及去年对应日期，资料取必要列当前全量。来源双读一致才发布；原始投影和解释私有归档；批次锁、校验、兼容指针原子切换，失败不推进水位，未知删除不静默丢行。历史版本不自动清理。

连接器读来源，product_board领域模块处理规则，仓储读写本地，路由处理协议。前端只走/api/v1，取聚合和分页；Ant Design控件/Table/Modal、Recharts图表、局部原型CSS。六区字段完整，筛选范围独立，409有限重新引导。收藏未证不作可信区间累计；推广归因比值标参考；缺标准保留十项当前值和原因，不造阈值或分数。规则诊断不冒充AI，人工期限/状态无数据明确未启用。

### 增长健康度：同款逐日动态判断（2026-11-02授权）

仅替换overview.health的固定返回。复用本请求已取得的product_daily_facts：当前筛选内的listing_id（店铺＋商品完整身份）与去年同月同日一对一配对，两期均使用交集记录；无对应行或2月29日无映射不补0。无新增SQL、表、索引、存储或同步；既有RR快照、资料筛选及版本绑定保留，health.py加入查询定义哈希。

三项只在共同配对行内计算：交易额求和，支付转化率＝买家合计÷访客合计，客单价＝金额合计÷买家合计；同比＝本期÷去年−1。按各指标必需字段检查空值/负值，分母须正；无效指标留空并说明原因，不平均逐日比率、不将字段缺失的行静默剔除。收入增长且任一可比效率指标下降，显示已确认的“规模增长、效率承压”；其他情况只给金额同比增长/下降/持平及各项实际变化，未确认的额外经营标签不启用。无配对或金额无同比基数给出具体说明，其他可算指标仍保留。结论明确限同款配对记录，不代表全店整体经营或上游日终完整。

验收先补失败回归，再实现；覆盖无配对、两侧独有行、跨店同ID、字段空值/负值、真实0、零分母、未舍入方向、跨月跨年与闰日、筛选及加权比率。使用隔离真实PG走发布/快照/查询，并对本机真实输入独立SQL复算；同输入比较去掉health后的总览响应、评分与明细，证明其他指标不变。前端保留条形布局及偏黄色，不再用“增长待验证”作默认经营结论。
