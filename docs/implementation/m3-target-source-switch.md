# M3 原版 GMV 目标切源设计与实施

本方案承接用户 2026-10-31 明确要求按原版目标完善开发版并本地发布；当前目标来源唯一采用 XGz Base 的 `tblwEjKpt1k51M3j`。完成额继续汇总相同固定六店的数仓店铺日成交原值，不重复扣退款或做单。技术栈沿 React/TypeScript、FastAPI、PostgreSQL 和独立同步任务；本轮不新增数据库结构或迁移。

## 对象、字段与约束

业务对象仍为渠道月目标及固定六店成员：`dataset_versions` 1:N `sales_targets`，每目标 1:N `sales_target_shops`，成员引用既有 `shops`。金额只存在目标头一次，不拆分到店，不存派生完成额、达成率或缺口，现有范式、索引及外键足够。没有新增缓存、事实表或经营来源。

最小来源投影固定四个字段 ID：平台 `fldGdr3oOJ`、年份 `fld5tezqp3`、月份 `fldnBczHp9` 均为 text；`gmv目标` `fldZq41Hnj` 为 number。来源单位为人民币元，Decimal 保留两位，不乘 10000。固定财年 2026-02～2027-01；表内历史月份仅留原投影并在规范化排除，未进入本财年合计。重复月份/record_id、非拼多多平台、无效期间和财年内非法金额拒绝；目标缺月与真实零保持原有状态区分。

只支持 `original_gmv` 一种 basis，使用独立行定义版本 `m3-original-gmv-targets-v2:original_gmv`。接口不接受旧 base/stretch；旧发布版本不以新定义解释，也不自动回退到 G1d 新表。源改名按 ID 映射，ID/类型不符则拒绝。四字段有界完整分页双读，逐页校验 Base/表/rev/时区/数量、分页终止与字段映射，双读内容必须一致。

复用既有任务锁、租约、发布事务、逐行/成员回读、不可变归档和幂等摘要。只追加本地目标版本及成员，原成功版本和归档保留，不删除历史。失败不推进唯一 `current_datasets` 指针；旧版 revision 与当前代码不相容时 API 明确拒绝，不静默混源。修复通过重新读取原版来源追加正确版本完成；回退须明确选择相容代码和精确旧版本，不自动回退来源。
