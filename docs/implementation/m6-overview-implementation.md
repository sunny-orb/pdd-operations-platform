# M6运营中心真实数据与共享导航实施方案

本方案对应2026-10-28用户授权：运营中心接真实最新数据，优先复用已接通页面接口，正文参照sites-current线上原型同样展示；共享顶部/左侧导航保留，顶部导航由开发调整、风格统一；未完善项入统一issues。执行状态只写TODO，来源证据/契约/实际验证分别维护。

## 展示与导航

保留各域日期条→“一屏掌握经营重点”摘要/月GMV/目标/动作/四入口/P0位置→四状态卡→四域卡→全部/P0/P1/P2预警→八列本日动作→全国关键天气/发布日切换→常显口径摘要/默认折叠来源记录。顶部调整为五个稳定看板入口并标当前页，保留共享外壳的侧目录/折叠/拖宽/窄屏行为。中心五区目录为overview、alerts、actions、weather、definitions；正文局部CSS复用线上必要结构，不搬旧全局body/topbar或经营快照。

固定3异常、3负责人、78分、历史fallback和ROI简化评级不生效。M6-01已按[data-contract](../data-contract.md#metric-m6-01)确认去重对象及售后父子分别计项；现行主卡沿线上名称显示“异常数量／待办动作”及首页预览范围，详细区列实际观察条数、未映射提示条数及逐域读取覆盖，不称全项目完整正式总数。正式P0/P1/P2仍NULL；页头改用已接商品／推广完整清单的来源P0去重计数并标注范围，不受六项预览限制。原因是：源域规则线索尚不足以自动确认为中心正式等级，未知不改为0。负责人/期限/进度为未登记，动作是来源建议。综合评分不适用及覆盖限制放入口径展开，不重算跨域加权分。各域日期独立、完整日未知，金额不同性质/期间不相加。

对象身份随每条观察传递`objectKey/objectLevel`：M1/M2仅以明确的`shop_id + listing_id`构造同一链接键，跨域多命中归为一个对象，不按商品裸ID、标题或品类合并商品。M5仅接受实际报告一致且明确的`report_id + object_level + object_key`；总览、品类、单款分层，不从标题推断分类。未提供完整身份的条目保留原观察、对象键为NULL，单列未映射且不猜数；全部未映射时对象数为NULL。成功读取可用观察清单且为空时才允许已接范围计0；M2 `insufficient_evidence`和M5 `pending_validation`的空占位清单标为“异常证据待核”，不计作可评估零，售后卡对象数为NULL。已有非空真实观察仍保留，不因整体待核而丢弃。读取失败、未接异常接口、未收到来源与失败保留旧观察分别显示，完整日仍见各域来源卡片。M5当前空priorities/actions不补造任何异常或建议；金额/正式风险待核不否定其固定词典和分类件数观察。

## 四域复用与接口职责

前端按实际职责拆分：`data.ts`管理各域异步状态及版本，`adapters.ts`映射领域返回值与短来源，`DomainCard.tsx`统一四张经营卡的展示/格式化，`SourceDetails.tsx`承载折叠的来源与更新记录及本地刷新入口，`SummaryCard.tsx`复用顶部四张状态卡，`AlertCenter.tsx`只管理预警等级/页码并对已接结果每页6条展示，`ActionsSection.tsx`独立管理动作表展示分页、列布局及完整文本提示，`DefinitionsSection.tsx`常显现行口径摘要，仅来源记录保持折叠，`OverviewPage.tsx`保留全量统计并组合区块；`presentation.ts`只按既有顺序取六项首页预览及对应建议，不增加规则或修改来源清单。卡片不自行取数或重算经营指标，不另建页面摘要缓存；“商品数据”仅为界面显示名称，商品模块/API身份不变。

预警默认仅显示首页预览，“查看全部预警”后才显示完整数量、来源优先级筛选及六条分页。动作同样默认首页对应建议，“查看全部建议”后保留全部原建议（含未出现在首页的对象）。返回首页预览重置等级及页码，预览随来源刷新，不固定缓存旧对象。预警组件在全部模式按buildCenterView输出的完整对象及来源优先级筛选，再切片分页，保留各来源定位参数；切换等级回首页、数据减少时夹到合法页，不重新取数或计算指标。CSS按六行槽位固定列表高度，完整说明通过提示层与默认折叠口径读取；分页不影响中心统计和动作表。

口径摘要使用静态article/header直接展示，不再包外层Collapse；来源记录保留单层默认折叠，箭头位于标题左侧。期间和入口直接使用各域card.valueLabel/link；观察覆盖复用主页面完整counts/coverage，未知不补0。详细来源按域结构化，保留真实元信息/错误与说明，仅对完全相同的说明字符串去重。展开不发请求，刷新仍调用原有本地元信息流程；不新增指标计算或源公式认证。

中心前端通过既有`/api/v1`四域API，各域独立元信息→固定版本查询，失败隔离，45秒/聚焦只检查本地元信息；变版取消旧请求、整组重取，409有界重试。同版本更新尝试/失败状态，不把未齐数标完整。

- M1复用products/meta，最新观察单日overview仅取交易额/日环比/同比；风险单独读products/risks，默认近31日与商品页共用期间函数，完整名单/来源等级/观察值/基准/变化/建议原样映射。风险定位保留返回period及main_listing，不额外追加main_shop；完整链接已含店铺身份，避免改变排名池。
- M2复用promotion/meta(mode=product)及最新单日overview/diagnosis：总花费/归因交易额/ROI/CTR/CVR；不使用店铺跨渠道合计ROI。诊断固定7日窗必须单列，不能当成最新单日结果。跳转带product_*与完整listing_id，#promotion-diagnosis。
- M3复用sales/filters、当月targets和最新单日performance/shops：月累计/目标/达成/缺店铺日/最新日值及店数。月份按负责域默认月，不因较旧观察日换成已过月目标。卡片入口携带`month=默认经营月`、`from/to=最新观察日`及`#performance`；无shop参数表示全部店铺，目标页负责参数校验与超批准范围提示。
- M5复用aftersales/meta与overview：真实报告身份/期间、总率/A/T及状态；现金额门禁不以旧报告填补。跳转必须带真实report_id和适用分类/关键词，#aftersales-analysis。整体/品类/单款不能重复加总。

中心只适配展示字段，不在前端重算经营金额/比率/增长/风险公式。源域优先级保留原标识；完整性/规则未核者为中心观察，不自动把域内P0当严重质量或已证紧急事件。来源已确认的业务规则和统一SOP沿data-contract，不新增一套中心评级。[SOP第13节](https://kocotree.feishu.cn/docx/EA2fdkbbLoMhYnxNEEvcxFhPnoc#doxcnZEotGQd2JcezVtoZJh6B9g)区分经营触发证据与根因验证，已证经营预警不能仅因根因待核降为观察；当前门禁针对输入和规则相容性：M1本地已确认单日订单规则不等同SOP第7节双7日支付买家规则，M2完整日及正式评级输入未齐，M5金额/相容比较和正式风险分支待核。上述缺口不能用固定分、模板负责人或旧中心阈值补齐。数据请求不会触发上游、模型、派单或业务消息。

## 天气对象、数据库与发布专用设计

天气不以城市观测或预报数值代替全国发布文本。唯一生效来源选NMC官网天气公报与中期预报两个互补文档；飞书公报页签仅作参考链接，无故障自动混源/回退。必要正文与真实发布时间有限读取、保留源URL；不读群、不发卡。天气独立于四域经营，失败不阻塞经营页。

在既有30经营表之外单列`weather_publications`一张天气发布归档表，追加Alembic07，不改冻结01基线/已执行迁移。它的对象是一份NMC公报发布日下、绑定两份真实原文及解析版本的不可变展示文档，非城市×日数值事实、非通用指标/任意配置。

字段：`id TEXT PK/FK→dataset_versions.id`；`issue_date DATE NOT NULL`（公报实际发布日，不用抓取日代替）；`revision_no BIGINT NOT NULL CHECK>=1`；`source_system TEXT NOT NULL CHECK='nmc_official'`；`content_sha256 TEXT NOT NULL CHECK64位小写hex`；`parser_revision TEXT NOT NULL`；`document JSONB NOT NULL`（固定Pydantic天气发布文档，见下述封闭结构）；`received_at TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp()`。UQ为(issue_date,revision_no)及content_sha256；索引(issue_date DESC,revision_no DESC,id)支持默认/历史选择。文档内容与源身份/时间、原文、解析版本共同进入hash，抓取时间不进入；同语义重跑复用，同日更正分配新修订，旧行不UPDATE/DELETE。

`document`是本发布产物的固定整体结构：title、issue_time、focus_regions、today_rain/today_temperature（regions/detail/status）、next_7_days（period/regions/detail/status数组）、sources（name/url/issue_time/text数组）、forecast_url、reference_url、group_card_link=NULL、note；不放经营金额、城市数值、其他业务FK或任意字段。整份发布文档作为不可变原文/解释产物有意保存JSONB，不另存会不一致的分组/过程/地区重复结果；日期/修订/摘要提供关系查询键。输入/输出按确定性解析可复算，私有原文证据与DB文档核对。天气表与dataset_versions为1:1；不伪造城市/店铺关联。既有task_runs要求成功必须引用真实dataset_versions结果，故复用weather_publication源版本，source_system=nmc_official，固定官方源定位/解释/必要原文引用、parser与实际适用窗；先draft插天气产物，再校验封版/原子发布。task_runs.result_version_id引用真实父版本，current_datasets.weather_publication指最新发布日最高修订，不因旧日补报倒退；不为天气放宽通用任务成功约束。子表仅允许向draft父版插入，已封版不可增改删；API只读published父版。source内容语义摘要和父版本包含解释/窗口的指纹区分，非两份可独立修改的经营指标。

权限：pdd_app仅SELECT；pdd_ingest仅SELECT/INSERT新表，不授UPDATE/DELETE/DDL。发布期按PG advisory锁串行/去重，失败记录task_runs并保留旧发布。先隔离真实PG验证迁移/幂等/修订/权限/失败恢复，再备份结构/授权并仅本机06→07；回退停天气任务后撤新表运行权限，已有业务数据拒绝破坏性降级。原30经营表字段/索引不改；派生天气SQL单独审阅，schema.sql从完整迁移链统一生成，含天气07；新库按[完整初始化流程](../database-schema/migration-plan.md#current-schema-delivery)一次执行，分段SQL仅供审阅。

## 天气API与更新

WeatherSection只控制简版/全文披露：今日长文三行预览，未来过程和来源记录用原生details展开，缺项及边界提示不随正文隐藏；按不可变publication.id重建展开状态。weatherFormat仅把带明确时区的合法ISO时刻格式化为上海中文时间，拒绝非法日期归一化，无时区/未识别文字原样保留。预报计数和地区并集来自现有document，不生成天气摘要结论；useWeather查询、历史ID及后端解析保持原职责。

`GET /api/v1/weather/meta`返回data_version/default_publication_id、各实际发布日最高修订列表、最新成功/尝试/失败及状态。`GET /api/v1/weather/publication?publication_id=...&data_version=...`返回固定document及meta；无记录明确source_unavailable，非法ID422，版本失效409。历史id可读，源更新不能把旧天气替换成当前页；两份源发布时间分别显示，不假称中期与公报同日同批。

解析必须识别“预计…08时至…”中的真实降水词，不能取第一段大风冒降水；当日气温没有明确时间证据时标未识别/待核，不从实况/此前/未来跨日泛化。下一7日为发布日起至+6日的过程展示范围，原文较宽或无法可靠裁剪时保留原句并标边界，不伪造成七条逐日预报。无文本命中不等于无天气风险。具体预报URL为官网当前入口时明确“当前官方预报”，不称历史原图。发布日/同日修订与日历缺口分别表达。

项目独立10/14/18调度加入weather来源步骤，每个时间槽最多原预算尝试；API/页面刷新不连NMC。机器/数据库不可用限制沿现有调度说明。

## 实施与验证步骤
