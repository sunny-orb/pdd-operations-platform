# 全项目来源同步实施方案（2026-10-28）

Goal：按`config/sync.toml`配置的每日时点串行刷新已接入来源；当前为Asia/Shanghai 10:00、10:30、11:00。原型仅约束布局/样式/字段，经营数据按各来源最新发布版本显示。

沿用独立Python任务、PostgreSQL30表和React只读API；本机使用单个launchd入口每分钟检查配置，业务API不启动调度。非敏感配置config/sync.toml，凭据独立0600私有文件，不进入Git/前端。当前本地环境自动启用，机器关机时不运行，恢复后本日漏点合并一次补跑。

## 对象、关联与更新

复用task_runs记录sync_project编排尝试及子来源任务；dataset_versions/current_datasets/coverage_records继续承载每个来源不可变版、当前入口、覆盖与状态，不新增表/索引/权限。全局PG advisory lock确保定时与手动入口串行，同一调度时间已成功则不重复；部分失败保留各来源上次成功版并记录失败。相容M1三来源/资料关系仍同事务切换；M2复用同一推广事实，不重复接入。

本地写入连接池固定最多3个连接、无额外溢出：项目编排锁占1个、评分发布锁占1个、评分只读RR快照占1个；取连接最多等待5秒。该预算不增加上游查询并发，上游任务保持串行。API使用自己的只读连接配置。

来源仍是已授权六店RPA/聚水潭加工/飞书退款必要投影；现已按M5专用方案加入售后JST必要投影和相容报告，不自动接入尚未完成的M6。对当前接入范围做稳定双读完整分页，更新原值/资料并形成新版本；已明确撤销的源键及身份变化通过受控全范围核对模式记录差异后发布新版本，旧版本不删除。普通不具备完整范围双读证明的入口仍拒绝不明缺行。完整读取投影与业务齐数是两件事，来源完整日仍unknown。

M1商品经营不再取推广/经营最小共同日期；按自身最新日取窗，推广独立标截至/缺项。上海昨日只排除未结束当天，不固定10月26日。前端元信息定期轻量检查本地API；新版本取消旧请求、重取当前组，默认日期跟随最新，用户自选范围保留。普通GET不触发上游。

## 实施步骤

1. 先补最新日期不被较慢源截断、调度时区/去重/改时间/失败重试及源修订的反例。
2. 实现配置、独立编排CLI、私有凭据、跨进程锁/任务状态及launchd安装/移除入口；同点去重和有限失败恢复真实PG验证。
3. 当前来源实际串行重拉一次，逐源报告时间/行数/失败；浏览器验证版本推进与明确状态。
4. 更新architecture/data-contract/TODO/issues/validation；检查、测试、构建及一轮最终独立复核后本地提交，不发布生产。执行状态统一见TODO，结果见validation。

## 验收重点

改值/缺键/身份更正可追溯且旧版不丢；未知完整性不标完整；时间修改热生效；进程重入不放大上游；单来源失败不毁其他独立来源；页面真实新版本自动渲染。

## 编排、修订与失败恢复细则

### 自动同步、手动补跑和历史修订（2026-10-28已授权）

本机采用**定时自动同步为主、手动同入口补跑为辅、范围内历史修订重查兜底**。已接入来源通过独立项目编排入口串行接收；尚未实现的模块不产生假同步。这些是同一套连接器/校验/发布流程的不同触发入口，不另建手动导入的一套口径。已有task_runs、dataset_versions、version_inputs、current_datasets、coverage_records承载尝试、幂等版本、输入、当前发布和覆盖，调度本身不增加物理表或Redis；天气的不可变文档独立归档，见下述专用设计。

调度时区固定Asia/Shanghai，当前每日10:00、10:30、11:00；2026-10-31按用户要求替换原10:00、14:00、18:00计划，每日仍三轮。唯一运行配置为`config/sync.toml`，每次检查重新读取，可用`scripts/sync-project.py --set-times`调整，无需重启API或重装定时器。这是已接入来源的全项目共用时点，只增加早间再次尝试的机会，不推定上游每天的完整交付时间，也不表示来源读取错误已经修复。独立launchd每分钟检查，单个项目入口持PG全局advisory锁并用task_runs按时间槽去重/最多两轮尝试；域任务仍用各自锁/租约。旧三个手工job入口同样受项目锁保护。每个数仓reader全部查询共享最多3次资源并发拒绝重试（2/6/15秒），普通语法/权限错不重试；不把本轮backend报错中的3推定为账号/全局额度。失败来源留旧版，独立来源继续，失败详情与成功时间分开。

本机已登录且机器/数据库可用时执行；关机/睡眠不能按时运行，恢复后当日漏点合并为最近一个时间槽，跨日自动补跑未启用。配置/调度独立于API，不在每个worker重复启动；公司生产调度、监控及运行环境仍另行验收。M1源与关系成功后才运行相容试行评分；源变而评分未出时隐藏旧分。页面45秒及聚焦轻量检查本地元信息，新版本重取并取消旧请求；默认日期推进，自选日期及其他筛选保留。

**调度与业务执行解耦。** 本机CLI与未来平台适配器调用同一`app.jobs.project_runtime.execute_project`，传入已有engine、稳定slot、显式运行路径及延迟取密函数；业务装配、来源接收/校验/发布、评分与报告由应用模块拥有。调度时槽/平台资源由触发器拥有，不向域模块传平台SDK；评分、运行、接收归档和配置/飞书工作根均显式定位。原互斥、租约、幂等及依赖规则不复制到新触发器。接口和整功能迁移/回退步骤见[sync-platform-handoff](sync-platform-handoff.md)，当前未接管平台。

当前手动更新使用同一CLI编排入口，返回任务/来源结果；网页手动提交任务的界面尚未实现。后续后台入口须立即返回任务ID/已有运行状态；选择来源、数据集和必要业务期间，指定期间补跑仍受原来源范围/权限和预算限制。若同逻辑范围已有任务在跑，登记/复用该任务或受控排队，不随点击量新增上游并发；手动任务与自动任务共用PostgreSQL互斥/租约和现有running唯一约束。普通看板刷新仅重读本地已发布结果，既不触发上游拉取，也不把接口等待变成长时间同步。用户只看当前真实进度、最后尝试/成功、实际截至/完整日和失败原因。

**增量及历史更正。** 有可靠修改时间/游标及稳定业务键才按增量读取，并使用交叠回看、分页同批/范围校验；dt通常是业务日，create_time通常是创建事件，均不自动充当修改水位。没有可靠增量时，按获准的完整范围快照/受控回看窗口重取并比对摘要；最近N天只能捕获窗口内修订，仍需周期更大范围对账与指定期间补跑，不能承诺旧退款或月结修订永远落在N天内。缺记录不代表删除；实际删除只依据明确删除事件/标记或已核完整枚举的范围快照，生成新版本并保留旧输入。当前项目编排对固定六店/批准日期范围执行两次完整分页且投影一致，再以受控reconcile_full_scope记录移除键/身份变更计数并发布新版本；既有行/版本不DELETE。普通未证明全范围的入口仍拒绝不明缺键；空商品/资料交付继续拒绝。读取枚举稳定不等于业务齐数，源软删除标签含义未证时只保留原值，不猜其业务效果。

**一次同步的边界。** 读取交付/固定批次→校验结构/键/单位/范围/完整性→在不可变候选版形成相容内容→短事务原子发布当前入口/可靠水位→按依赖重算资料关系、评分/报告→公布真实状态。上游有快照/批次令牌就固定它；分页读取中途上游变化且无法证明相容时不能把混批当完整成功，应有界重读或保留候选并说明缺口。源拉取不持有长时间发布事务/当前入口锁；数据无语义变化时复用已存内容版，但仍记录本次实际尝试与来源时间观测。新事实可先发布，依赖旧评分时明确待重算；未验依赖不拼成“全正常”。

首期单来源串行起步，跨源总并发仍按核实预算控制；执行互斥与失败接管复用[PostgreSQL锁机制](https://www.postgresql.org/docs/17/explicit-locking.html)及现有任务设计，发布/读取的一致性依据[事务隔离](https://www.postgresql.org/docs/17/transaction-iso.html)。调度到点不保证上游已有新数据，也不代表业务齐数。M3完成额随shop_daily新版本按已确认方案A重新汇总，已发布历史售后报告仍固定旧输入；更新历史报告须生成新报告修订。

“上游最多5并发”尚未确认，连接与查询、账号/资源组/全局、独享/共享、队列/拒绝及同步额度分别核实。连接池和任务遵守总预算，不随用户或API进程数放大。
