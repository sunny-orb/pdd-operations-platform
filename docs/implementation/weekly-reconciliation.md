# 每周对账与失败隔离实施计划

> 按用户2026-11-11已确认方案连续本地实现；使用subagent-driven-development。原业务口径、其他来源调度及历史报告不变。

**Goal:** 每周日17:00北京时间对原8张数仓来源兜底核对，失败来源结束后每5分钟重试直至成功；普通时点仅接收未接受的变化。
**Architecture:** PostgreSQL持久化每来源对账周期、状态、结束与重试时刻；复用既有跨进程来源锁和发布器。对账状态与变化接收/检查状态分离；不引入新服务。
**Tech Stack:** 现有Python/PostgreSQL/Alembic、React/TypeScript。
**Spec:** 本文及本轮已批准聊天方案；字段方案在编码前保存docs/database-schema/weekly-reconciliation.md。

## Global Constraints

- 仅本地代码与随机本机PG测试；不推送、不部署、不修改生产DB、服务器或网络。1064调查只读现有项目日志和必要已授权来源证据，不执行上游ETL或业务同步。
- 每周日17:00 Asia/Shanghai；同一来源失败结束后至少300秒再试，无次数上限；成功来源本周期不再拉取，重启恢复，跨周未完成不重复建任务。
- 原16:10改成普通变化检查；变化接收失败保旧并保留有限重试，额外对账失败不能污染变化同步状态。成功须完整接收/校验/必要发布，来源前后变化不得错误推进接收水位。
- 同一来源不并发，长任务和进程崩溃有明确恢复语义；持续失败页面和结构化日志告警，不发业务消息。
- 保留预存TODO.md、docs/issues.md、docs/validation/2026-11-09.md修改，不混入提交。基线1ef5202；不改主工作区。

## Review Focus

1. 周日17点前后/UTC换日/重启错过时点：只运行到期周期，不立即补跑部署前所有历史周。
2. 慢任务、崩溃、多个worker：锁防重复，重试起点为结束时间，维护延后不得冒充成功。
3. 周期跨周仍失败、普通变化与对账同轮：一来源一次读取，独立结果，成功不重复。
4. 上游标记变动/检查失败：旧数据仍可用，不能因额外对账失败伪造业务过期或因校验未完成判成功。
5. 新迁移对初始化/保留/恢复目录校验影响：按新增对象适配，不降低未知对象拒绝保护。
