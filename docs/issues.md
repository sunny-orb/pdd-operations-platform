# 项目问题台账

统一记录每个页面交付后仍存在的真实缺口，便于后续逐项完善。项目实施进度只看[TODO](../TODO.md)；需求、指标定义和原始证据仍分别维护在requirements、data-contract和source-evidence，本台账通过链接引用。

## 维护规则

- 每页交付前逐项复查，优先在本次完成修复；确实无法完善的才登记，不把记录问题当成提前停止实施的理由。
- 每项写清现象、影响、页面当前怎样显示、后续关闭条件及证据。来源不可用、业务口径待核、技术缺陷和验收缺口分开记录，不将缺数补零或待核值标为可信。
- 编号固定、原行更新；解决后保留关闭日期、提交和真实验证摘要，不删除记录或每轮另建问题文档。不凭代码检查、健康检查或合成样例关闭真实数据/视觉问题。
- 尚未重构交付的页面注明未交付，不能把“尚未核查”写成“没有问题”。跨页共性问题只登记一次。
