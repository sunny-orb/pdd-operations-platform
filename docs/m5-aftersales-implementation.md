## 来源与数据库专用设计

对象为J1确认期间退货原行、J2/J3支付期间已发货/已取消销售原行、固定期间报告及其版本/规则/比较引用。复用`return_records`、`product_sales_records`、`aftersales_reports`及版本/覆盖/规则表；原行1:N归输入版本，报告1:1归结果版本、经version_inputs N:1引用固定三输入，不以款号建逐单外键。原键/完整组键、分母唯一归属、类型/空值/约束和范式以database-schema/02、03、04为准；不复制粗销售分母给多个细退货组。

源范围遵守data-contract2.0，数仓优先。先核候选表必要字段/注释和日期/状态，再对必要真实数据验证Q=实退数量、A=实际入库金额、S=已发货实发金额、P=已取消销售金额及六店范围；未证明对应时不映射相近术语、不用M1/M3金额替换。上游仍只读、串行、有界退避，凭据走现有私有配置。没有确证三输入时对应指标不可用，不从旧报告数字填充最新结果。

金额/数量NUMERIC、ID TEXT、API十进制字符串。J1确认时间和J2/J3支付时间保留不同依据；最大观察日期不证明齐数。期间头不伪写成每原行日期。新输入/修订追加不可变版本、保留旧行；稳定全范围读取验证后才发布入口。报告固定相容输入/规则/比较修订，失败不推进水位；同语义重跑幂等，补旧期不使默认入口退回。全量原行先独立聚合，保留无退货销售组，Top只用于展示；缺/冲突身份返回明确状态。主数据库沿用PG，当前不增加缓存或结果表。如需要本地writer权限，追加最小权限Alembic，先真实PG验证、备份及受控升级；不改既有revision或服务启动建表。

## API与职责

前端只访问`/api/v1/aftersales`。路由处理参数/协议；repository固定只读RR报告快照、输入版本及来源状态；service/metrics处理筛选/分组/三率及比较；连接器/发布任务处理来源校验和入库。默认报告按实际period_end及既定类型/修订顺序选最新，源更新后45秒/聚焦轻量检查，默认跟随、自选报告保留。

- `GET /meta`：数据版本、默认报告、实际日期/期间、完整性、各源最近成功/尝试/失败、报告可用状态。
- `GET /options`：报告列表及选定报告品类、失效筛选说明。
- `GET /overview`：固定报告/筛选下九指标、风险/建议状态、阶段/尺码、原因/近8期趋势所需聚合投影；不返回全量原行。
- `GET /analysis`：六标签(category/style/mom/yoy/quality/history)，后端分页，保留原列；报告级历史等区明确标范围。比较按完整组键，零分母/缺报告/缺输入不可比。

正常`data/meta`，非法参数422，未连接/缺输入为明确状态，来源故障不变为真实零；版本变化409，前端整组重取/取消旧请求。GET不访问上游、不新建任务。
