# 全项目来源同步实施方案（2026-10-28）

Goal：每日Asia/Shanghai 10:00、14:00、18:00串行刷新已接入来源，时间可配置；原型仅约束布局/样式/字段，经营数据按各来源最新发布版本显示。

沿用独立Python任务、PostgreSQL30表和React只读API；本机使用单个launchd入口每分钟检查配置，业务API不启动调度。非敏感配置config/sync.toml，凭据独立0600私有文件，不进入Git/前端。当前本地环境自动启用，机器关机时不运行，恢复后本日漏点合并一次补跑。

## 对象、关联与更新

复用task_runs记录sync_project编排尝试及子来源任务；dataset_versions/current_datasets/coverage_records继续承载每个来源不可变版、当前入口、覆盖与状态，不新增表/索引/权限。全局PG advisory lock确保定时与手动入口串行，同一调度时间已成功则不重复；部分失败保留各来源上次成功版并记录失败。相容M1三来源/资料关系仍同事务切换；M2复用同一推广事实，不重复接入。

本地写入连接池固定最多3个连接、无额外溢出：项目编排锁占1个、评分发布锁占1个、评分只读RR快照占1个；取连接最多等待5秒。该预算不增加上游查询并发，上游任务保持串行。API使用自己的只读连接配置。

来源仍是已授权六店RPA/聚水潭加工/飞书退款必要投影；现已按M5专用方案加入售后JST必要投影和相容报告，不自动接入尚未完成的M6。对当前接入范围做稳定双读完整分页，更新原值/资料并形成新版本；已明确撤销的源键及身份变化通过受控全范围核对模式记录差异后发布新版本，旧版本不删除。普通不具备完整范围双读证明的入口仍拒绝不明缺行。完整读取投影与业务齐数是两件事，来源完整日仍unknown。

M1商品经营不再取推广/经营最小共同日期；按自身最新日取窗，推广独立标截至/缺项。上海昨日只排除未结束当天，不固定10月26日。前端元信息定期轻量检查本地API；新版本取消旧请求、重取当前组，默认日期跟随最新，用户自选范围保留。普通GET不触发上游。

## 实施步骤

1. 先补最新日期不被较慢源截断、调度时区/去重/改时间/失败重试及源修订的反例。
2. 实现配置、独立编排CLI、私有凭据、跨进程锁/任务状态及launchd安装/移除入口；同点去重和有限失败恢复真实PG验证。
3. 当前来源实际串行重拉一次，逐源报告时间/行数/失败；浏览器验证版本推进与明确状态。
4. 更新architecture/data-contract/TODO/issues/validation；检查、测试、构建及一轮最终独立复核后本地提交，不发布生产。执行状态统一见TODO，结果见validation。

## 验收重点

改值/缺键/身份更正可追溯且旧版不丢；未知完整性不标完整；时间修改热生效；进程重入不放大上游；单来源失败不毁其他独立来源；页面真实新版本自动渲染。
