# 内容复用本地验证（2026-11-10）

本轮范围：独立工作树`codex/database-content-reuse`，基线`9475ab2`。只用本机PostgreSQL17的随机新建测试库与合成数据；未连接生产数据库或上游，未修改服务器、删除线上数据、推送或部署。字段设计见[专用字典](../database-schema/content-reuse.md)，进度见[TODO](../../TODO.md)。

## 行为与保护

- 五类大事实通过不可变内容块复用；保留旧物理事实及全部版本关系，当前查询同时兼容两种表示。按业务日期/统计期间再分64桶，避免滑动窗口牵连其他日期；无跨数据集、表或行语义修订的复用。
- 一次完整版本只有一种存储表示；发布前逐值重读并保留原校验。增补、修订、删除改变新成员清单，已发布报告仍绑定原输入。来源读取仍为既有范围的完整核对，不能把本地内容复用称为上游增量同步。
- 默认`CONTENT_REUSE_ENABLED=false`；开启后写入口仍硬限制`127.0.0.1:55432`、`pdd_admin`及随机测试库名。普通项目库/生产不能以环境变量绕过。原始接收归档仍沿原生命周期，未改变来源或指标。
- 新schema为14；保留模块适配新目录和保护函数，所有共享版本及其输入都在保留闭包。没有共享块GC、生产存量转换或删除脚本。13版归档包不能直接套用到14版，须专门适配后再验收。
- 新视图要求先完成相容迁移；本轮仅本地验证，不能将当前代码直接覆盖未升级的生产库。降级仅共享对象及14归档证据都为空时允许，拒绝以丢数据换回退。

## 容量与性能实测

命令：`apps/api/.venv/bin/python scripts/benchmark-content-reuse.py`。本机Docker PG17、60天×500行/天、连续6版，窗口每日前移并更正前一天2%的记录；共180000行逻辑事实。空间含对应索引，复用侧包含3张引用/登记表；不含两边等价的普通版本元数据。查询为最新整版COUNT与NUMERIC SUM，7次取中位值，结果逐项相同。不是线上负载、并发或p95验收。

| 项目                |              旧整版存储 |                内容复用 |
| ------------------- | ----------------------: | ----------------------: |
| 物理事实行数        |                  180000 |                   32893 |
| 事实及必要引用/索引 | 59383808 B（56.63 MiB） | 20070400 B（19.14 MiB） |
| 首版写入            |                1.6796 s |                5.7805 s |
| 后续每版写入        |         1.7691—1.8440 s |         0.5820—0.6123 s |
| 最新整版聚合查询    |                4.044 ms |                6.982 ms |

完整合成结果见[基准JSON](content-reuse-benchmark.json)。

该样例空间减少约66.2%，后续每版仅新增72—74个块、复用约3764—3766个块。首次写入和查询均有额外成本，不能只报告节省；大型历史区间内大量分散修订可能重写更多块，物理行也不等于严格逐行去重。真实新增日期/修订与版本引用仍会增长。

本机外置`部署/backup-support.py`只调整审核过的表清单（14为含Alembic的46表），没有执行其远端或凭据函数；实际全量备份仍由pg_dump包含视图，不能把候选单版本恢复包当全库备份。该本机文件不在本仓库提交中。
