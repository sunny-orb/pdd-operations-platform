# 每周数仓对账与失败隔离验证

日期为2026-11-11。验证范围为本地工作树、随机本机PostgreSQL和前端合成输入。数仓读取、发布内容和实际调度间隔通过合成边界、真实数据库和注入时钟核对。

| 核验               | 输入和预期                                                                                                                                                                                                                                                         |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 普通时点与首次对账 | 16:10的来源标记未变时只检查。周日17:00北京时间命中八张数仓来源的获准范围接收，飞书在此时没有附加接收。首次启用登记当周到期或未来周期，手工接收不消费该周期。                                                                                                       |
| 独立失败与重启     | 成功来源停至下一周。单源失败等待结束后300秒，299秒不启动，连续失败超过既有普通任务预算仍可重试。新连接复用已登记周期，停机错过周日及失败跨周继续原周期。                                                                                                           |
| 慢任务与锁         | 模拟接收耗时12分钟，重入同一PG项目锁返回already_running。中断后由持锁新执行者确认并等待，防止并发或立即重复读取。                                                                                                                                                  |
| 接收和水位         | 维护延后继续待对账。接收后标记变化或检查失败保留已接受水位。普通检查与对账同轮共用一次读取；稳定对账只关闭匹配的普通待接收失败。                                                                                                                                   |
| 已有数据和页面提示 | 真实PG已发布商品版本继续可用，检查状态保留，接口单独返回对账失败、上次结束及下次重试。组件显示数据可用及独立异常，可按异常定位展开。                                                                                                                               |
| 数据库与权限       | 升级15、空状态降级再升级、有记录拒绝降级、表权限及状态检查约束。空库SQL与Alembic逐项比对结构、权限和触发器，保留/归档范围识别新增状态表，未知对象拒绝规则仍生效。                                                                                                  |
| 1064安全诊断       | 注入明确的数仓并发拒绝，项目运行stdout与任务JSON均记录分类、阶段和已耗用重试次数；不记录驱动原文、SQL、参数或秘密。历史两次1064保存的材料只够确定失败发生在读取执行阶段，具体原因仍待证据。见[原始记录核查](../source-evidence.md#product-sync-failure-20261110)。 |

浏览器自动操作因Work设置禁用本地浏览器而未执行。组件交互由Vitest覆盖；准备了仅在本机监听的合成预览。实际来源、完整日、运行环境与发布另行验收。

定向后端验证共28项通过，覆盖调度、状态兼容、归档恢复及安全日志。前端对账状态专项、`npm run check` 和 `npm run build` 通过。

审查追加两项真实PG回归。第一次周对账失败和维护暂缓时，保留已有版本与旧普通任务的异常记录，下一次稳定普通接收后关闭。普通接收未确认水位后，即使标记回到旧值且期间检查失败，下个普通时点仍复验。受影响后端79项和前端19项专项通过。
